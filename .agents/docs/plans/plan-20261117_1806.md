# Close the 2026-11-17 architecture audit — fix the findings that are code, record the ones that are not

## Objective

`audit-20261117_1734.md` found 35 issues across the layers and the implemented modules: two high (any signed-in account can replace or delete stored files and serve script from the app origin; OIDC tokens outlive the account standing that issued them), thirteen medium, fifteen low and five info. This plan fixes every finding that is a code or schema defect (F-01 to F-04, F-06 to F-08, F-11, F-15 to F-28, F-30, F-31, the token half of F-33, F-34), settles the documentation drift (F-10, F-14, F-32) and records the findings the owner keeps as accepted or parked (F-05, F-09's splits, F-12, F-13, F-29, F-35, and the deletion-safety half of F-33) in the ledger with their reopen triggers. After it lands the audit flips to `resolved`. The boundary it does not cross: no new product surface, no change to the wire contract's shape beyond the refusals named below, and no top-level directory added.

## Current state (verified in the tree, 2026-11-17)

## Decisions

All decisions below are dated 2026-11-17 and take effect when the owner approves this plan; each carries the option the audit recommended unless a line says it moved. The owner may veto any of them before "continue with phase 1".

- **D1 (2026-11-17): uploads are owner-bound, finals are immutable through tus, and `/storage` answers sandboxed.** `TusHandler` takes an `Owner(*http.Request) string` option (the framework never learns the caller type); `TusBegin` records it in the manifest metadata under `owner`; `HEAD`, `PATCH` and `DELETE` act only on a session whose owner matches and answer the not-found shape otherwise; creating over an existing final object answers 409; `TusDiscard` refuses a row without the tus marker. `/storage` adds `Content-Security-Policy: sandbox; default-src 'none'` to every response and `Content-Disposition: attachment` for any type outside an inline allowlist (`image/png`, `image/jpeg`, `image/gif`, `image/webp`, `image/avif`; not SVG). The cost: a legitimate client cannot re-upload over a stored key and must delete through the feature that owns it; SVG and HTML download instead of render. Rejected: per-bucket upload grants — a product model nobody has specified, and it would not close overwrite by itself. Rejected: content sniffing to pick the served type — still same-origin, and it adds a parser to a hot path. Rejected: a separate assets origin — right in the end for hostile content, but a deployment change that no fix here should depend on; recorded in the roadmap as the follow-up.
- **D2 (2026-11-17): the protocol store pulls account state at refresh time instead of being pushed a revocation.** The grant handler, for `GrantRefreshToken`, reads the account through the user directory federation already uses and refuses with `invalid_grant` when the account is disabled, banned, gone, or no longer admitted by a restricted client's group list; the refused grant's rows are deleted. `userInfoClaims` answers the subject only for the same accounts. Access tokens already issued live to their own expiry (60 minutes by default). The cost: one account read per refresh (the claim builders already do it) and a bounded window instead of instant cut-off. Rejected: push revocation from the ban, disable, delete and group paths — identity cannot import federation, so it needs a composition-root seam and four call sites, and it still misses the next state change someone adds. Rejected: only shorten the refresh windows — leaves the hole, narrower.
- **D3 (2026-11-17, moved from "boundary fold first" to the column type): `users.email` becomes `CITEXT` in migration `00004`, edited in place.** The database then guarantees uniqueness and lookups whatever a caller forgets; the Go comparisons that matter (`ErrSameEmail`, collision scans) use `strings.EqualFold`. The cost: the stored address keeps the case the user typed, and tests that insert a mixed-case pair must change. Rejected: lower-casing at every write and lookup — six call sites already differ and the next one will too. Rejected: an additive `ALTER` — the owner's migration policy for this plan is in-place edits.
- **D4 (2026-11-17, moved from the audit's option (a)): an SSO match on an unverified local account adopts it.** In one transaction the linking clears the credentials the unverified row holds (password, TOTP and recovery codes, API keys, sessions, pending tokens), stamps `email_verified_at`, links the identity and records an audit event. The audit's option (a), refusing until the code is entered, leaves the attacker's password in the row and is not a fix. The cost: an account that someone legitimately created and never verified loses its password the first time the verified owner signs in through SSO. Rejected: refuse and ask for the code — does not remove the planted credential. Rejected: purge unverified accounts by age — a separate retention rule, parked in the ledger.
- **D5 (2026-11-17): `RequestEmailChange` and `DeleteMyAccount` become `Session` with `StepUp`.** `ConfirmEmailChange` stays public (the code is its credential). API-key callers lose both procedures, which is the point. The SPA wraps both in the existing `useStepUp` runner. Rejected: keep `Authenticated` and rely on the old-address notice — the notice is best-effort and arrives after the change.
- **D6 (2026-11-17): the failure ledger counts second-factor failures and locks once.** A wrong TOTP or recovery code increments the same `failed_attempts` streak through a seam on the sign-in issuer; the streak is zeroed when a sign-in completes (the password path with no factor, `CompleteSignIn` on success), not when the password verifies; the lockout lands when the count reaches the bound and a partial unique index on the open lockout makes the insert a no-op for later failures, with the notice and audit record written only when a row landed. The default bound drops from 100 to 10 (the reader's floor stays 5). The ban, disable and lockout switch runs before the bridge is minted. The cost: a user who fumbles ten codes is locked for an hour, and the unique index is edited into `00004`. Rejected: a separate MFA counter — two ledgers to reset, and the lockout is one concept. Rejected: keeping 100 — the audit shows it allows a continuous drip.
- **D7 (2026-11-17): the last-administrator guard is one function used by delete, role replacement, ban and disable.** `user` exports `EnsureAnotherAdministrator(ctx, tx, userID)`; `authorization` already imports `user`. Rejected: leave role replacement to the boot-time warning — the repair is a CLI run.
- **D8 (2026-11-17): the newest active key signs, every active key verifies, and the opened keys are cached for 30 seconds.** `ActiveSigningKeyPairs` orders by `created_at DESC, key_id`; verification uses the published public set by `kid`; the algorithm and the opened private key are cached with a 30-second TTL and dropped on `invalidateStaleSeals`, so a `jwks:generate` from the CLI takes effect on the running process within 30 seconds and the old key keeps verifying until it is retired. The cost: a signing-key change is not instant. Rejected: caching forever with a signal — the CLI is a separate process. Rejected: leaving the per-request read — it is two queries and a private-key decrypt per request.
- **D9 (2026-11-17): the limiter fails closed for the credential and code buckets.** `RateClass` gains `FailClosed`; the registry sets it for `guard.RateAuth`; a limiter error then answers 503 with `Retry-After` in the surface's own protocol; the default bucket stays open. The cost: a database fault now blocks sign-in as well as everything else, which is already true of sign-in itself. Rejected: a dedicated limiter pool — more infrastructure for the same outcome.
- **D10 (2026-11-17): outbound network policy lives in the fetcher, at dial time.** `fetcher.Options` gains `AllowPrivateNetwork` (zero value false); a `net.Dialer.Control` refuses loopback, private, link-local, unspecified, multicast, `100.64.0.0/10`, `192.0.0.0/24`, `198.18.0.0/15` and `240.0.0.0/4` after resolution, so rebinding cannot pass; the webhook pre-check is deleted; `webhook.allow_private_network` is removed and `fetcher.allow_private_network` (default false) replaces it, with the development and E2E configs setting it true. The cost: one key renamed with no alias, and every dev setup that points a provider at localhost sets the new key. Rejected: keep the webhook-only check and add the missing ranges — leaves rebinding and five call sites.
- **D11 (2026-11-17): a retired refresh token leaves a tombstone, and an unreadable window fails the grant.** Rotation rewrites the retired pointer to a marker instead of deleting it; presenting a marker deletes the grant and answers `invalid_grant`. A failed read of the refresh-window setting returns an error from the grant handler instead of minting a token with no expiry. Rejected: keep deletion and add nothing — a thief who refreshes first keeps the chain unnoticed.
- **D12 (2026-11-17): watch streams end at the access token's expiry and are capped at five per account.** `jwtutils.Caller` carries `ExpiresAt`; the stream selects on a timer for it; `Subscribe` refuses the sixth stream with `resource_exhausted`. The client reconnects with the refreshed token. Rejected: periodic re-validation against the database — the expiry is the credential's own lifetime.
- **D13 (2026-11-17): jobs and modules are one-way.** Task payload types and their `QueueConfig` move to a leaf package `internal/jobs/tasks` that imports only `framework/queue`; the eleven notifier constructors move into the modules that call them; processors stay in `internal/jobs` and import modules and `tasks`. A boundary check refuses `modules/**` importing anything under `internal/jobs` except `tasks`. Rejected: leaving it and recording the risk — the next processor that needs `verification` or `federation` closes the cycle under deadline pressure.
- **D14 (2026-11-17): uploads, storage serving and the queue/scheduler admin become modules.** `modules/storage` mounts `/api/uploads` and `/storage/*`, resolving the manager and signer in `Mount` so a missing engine fails `Prewarm`; a new area `modules/operations` carries the queue and scheduler procedures with a service and the recorder inside it; `router.Options` loses `QueueClient`, `Scheduler`, `DB`, `Audit`, and keeps `Injector` for the debug devtool only. `GET /storage/*` and `HEAD /storage/*` get `Public` rules. The cost: `/storage` now sits inside the module group (unclassified paths are not throttled, so the budget is unchanged), and the move runs after phases 1 to 9 so it carries finished code. Rejected: document the exception — the audit shows F-15 lived in exactly this unowned code.

## Execution rules

- **Atomic commit per phase** is authorized; each phase's heading names its suggested commit message; self-serve commits are allowed during this plan's working session. The plan, `audit-20261117_1734.md` and the audit's `index.md` row land in phase 1's commit.
- **Execution waits for the owner's explicit instruction**, phase by phase ("continue with phase N"). When the phases have all landed, the agent stops and recommends the closing commit message with its paths — it does not commit the closing state on its own.
- **Migration policy (the owner's grant for this plan):** no `ALTER`. Schema changes are made by editing the migration file in place (`00004`, `00008`, `00013`). The local development database may be reset with `task run -- migrate:reset --force --up` then `task run -- migrate:seed --force` when an edited migration needs it; the reset targets only the database this work created. Applied sets are never renumbered. Each phase that edits a migration says so and runs the reset before its validation.
- **Compatibility policy (the owner's grant for this plan):** the project is early stage; no backward compatibility, no aliases, no fallback readers, no legacy code. A renamed key, a removed procedure answer or a changed refusal is replaced outright; every caller, test, fixture, doc and E2E scenario changes in the same phase.
- **The owner's parallel work is untouchable:** none named for this session; the working tree at plan time carried only this plan's documents.
- **Per-phase validation runs before each phase's commit.** From phase 7 on, `go test -race` over the touched packages joins it.
- **Docs ride the phase that changes the behavior when the change is a contract line; the full sweep is phases 12 to 14.** A phase never leaves `rules.md` claiming what the code no longer does.
- **E2E only when relevant** — phases 1, 3, 4 and 10 name theirs; every other phase records n/a with the reason, never silently.
- **Static-analysis findings are leads.** The dead-code removals in phases 4 and 11 name the search that proved each unreachable.
