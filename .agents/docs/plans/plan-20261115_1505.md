# Emailed codes take one shape — three letters, five digits, uppercase

## Objective

Every code `modules/identity` mails to a person, and the device-login
user code beside it, is a random string today (`GtYqzSzbSHeZ`, twelve characters; six for the short
one-time window). The owner wants one format: **uppercase, three letters
then five digits, eight characters** (`KQM48215`). This plan replaces the
six generators with one, makes the verifying side case-insensitive, and
moves the webapp's code entries, the email preview, and the E2E mail
readers to the new length.

No schema change: every code is stored as a SHA-256 hash in a `TEXT`
column. No backward compatibility: a code issued before the change is
dead, which on a development database is a reset.

## Current state (verified in the tree, 2026-11-15)

- **Five emailed-code generators, all `crypto.RandomString` over
  `AlphabetUnambiguous`** (`pkg/crypto/token.go:21`, mixed case, no
  `0 1 I O l`):

  | Flow | Generator | Length |
  | --- | --- | --- |
  | Email verification and email change | `newVerificationCode`, `modules/identity/verification/service.go:79` | 12 (`:73`) |
  | Password reset | `modules/identity/password/recovery_service.go:318` | 12 (`:67`) |
  | One-time access | `generateCode(ttl)`, `modules/identity/onetimeaccess/service.go:433` | 6 when the window is ≤15 min, else 12 (`:78-86`) |
  | OAuth sign-in confirmation | `modules/identity/oauthsso/resolution.go:339` | 12 (`:43`) |
  | Re-authentication | `modules/identity/webauthn/reauth.go:94` | 12 (`:70`) |

- **Verification is a case-sensitive hash match.** The presented string
  goes to `crypto.HashHexToken` untouched at `verification/service.go:247`
  and `:528`, `recovery_service.go:357` and `:415`,
  `onetimeaccess/service.go:182`, `reauth.go:163`. Only the OAuth flow
  trims (`resolution.go:306`, `strings.TrimSpace`); nothing folds case.
  An uppercase-only code typed in lowercase would be refused unless a
  normalizer is added.
- **The device-login user code is the sixth consumer.** Its own
  eight-character generator over `23456789ABCDEFGHJKMNPQRSTUVWXYZ`
  (`modules/devicelogin/service.go:25`, `:242`), a `XXXX-XXXX` display
  hyphen (`FormatUserCode`, `:256`, served as `user_code` at `:84` and
  `:110`), and its own `NormalizeUserCode` (`:265`) that folds case and
  strips the hyphen. The webapp page splits eight slots 4|4
  (`-device-view.tsx:38-45`, `:195-216`).
- **The wire does not constrain the code.** The proto fields are
  `min_len = 1` (`api/connect/webauthn.proto:112`,
  `api/connect/authn.proto:109`) — no pattern, no length. No contract
  change, so no `rpc:stale` drift and no Yaak row moves.
- **Guess budgets differ per flow.** One-time access counts wrong
  device pairs (`maxAttempts = 5`, `onetimeaccess/service.go:27`); the
  OAuth flow keeps strikes (`oauthsso/repository.go:488`). Verification,
  reset, and re-authentication carry no per-code attempt counter in the
  service — they lean on the rate limiter.
- **The webapp hard-codes the length.** `verify-email.tsx:29`
  (`CODE_LENGTH = 12`, twelve `OTPFieldSlot`s,
  `styles/pages/verify-email.stylex.ts:6`); the reset screen takes a free
  `Input` (`(auth)/-reset-password-view.tsx:39`); the re-authentication
  dialog sends the typed code as-is
  (`libraries/reauth/-reauthenticate-dialog.tsx:118`). The device page
  already normalizes to uppercase at eight (`-device-view.tsx:38-45`).
- **The E2E readers pin the old shapes.**
  `packages/e2e-tests/workflow/helpers.ts:190` (`/^[A-Za-z0-9]{12,26}$/`),
  `:206` (`input[maxlength="12"]`), and
  `sign-in-completeness.test.ts:46` (`/^[A-Za-z0-9]{6}$/`).
- **Prose claims the old lengths:** `docs/auth.md:14` and `:79`,
  `docs/api-endpoint.md:40`, `.agents/docs/endpoint-reference.md:116`, `:935`,

## Decisions

The owner confirmed D1, D2, and D4 on 2026-11-15; D6 is the agent's proposal and waits for approval.

- **D1 (owner-confirmed 2026-11-15): six codes in scope.** The five in
  `modules/identity` plus the device-login user code. One-time access
  loses its short/long split — one length for every window — and
  `generateCode` drops its `ttl` parameter. Rejected: keeping the
  six/twelve split with a new alphabet (the owner asked for one fixed
  shape).
- **D2 (owner-confirmed 2026-11-15): the alphabet drops the glyphs a
  person misreads.** Letters `A–Z` without `I` and `O` (24), digits
  `2–9` (8): the codes are typed from a phone reading an email, the
  contract `crypto/token.go:15-18` already states. Entropy is
  24³ × 8⁵ ≈ 4.5 × 10⁸ (about 29 bits). Rejected: full `A–Z` and
  `0–9` — about 31 bits, two bits more at the price of `0/O` and `1/I`
  confusion.
- **D3: one generator, one normalizer, in `pkg/crypto`.**
  `RandomLetterDigitCode()` draws the letters then the digits;
  `NormalizeCode(string)` trims, uppercases, and drops the hyphens and
  inner spaces a person types while copying. Every verify site hashes
  `NormalizeCode(presented)`, so a code typed in lowercase or with
  stray whitespace resolves. Rejected: per-module copies (five drifts
  waiting) and a hyphen display (`ABC-12345` — the owner's format has
  none).
- **D4 (owner-confirmed 2026-11-15, amended by the trace the same day):
  the credential bucket guards the guessable calls.** The drop from about
  69 bits to about 29 bits makes guessing the residual risk; a code lives
  an hour (`verification/service.go:68`) and is single-use. The owner's
  pick was a tighter bucket for the verify, reset, and re-authentication
  calls; the trace of `internal/guard/ratelimit.go` showed they were
  already in the strictest bucket (`RateAuth`, `rate_limit.auth_limit`,
  10 a minute per client), so there was nothing tighter to move them to.
  The one gap was the session-guarded device `Inspect` and `Decide`,
  counted nowhere; they joined `RateAuthProcedures` (`48ab3152`), with the
  table test extended. Consequence: a distributed guesser is not stopped
  by a per-address key. Rejected: a strike column on each token row (a
  schema surface for five tables) — the answer if that risk grows.
- **D5: no schema change, one wire-value change.** The proto fields stay
  `min_len = 1`; a pattern constraint is a contract change the owner did
  not ask for. Migrations stay untouched (hash columns are `TEXT`). The
  device-login `user_code` answer loses its hyphen (`ABC12345`, not
  `XXXX-XXXX`) — a value change, not a shape change, so the generated
  clients do not move.
- **D6 (agent-proposed, confirm at approval): the device code drops its
  hyphen display.** One format everywhere; the page keeps a 3|5 visual
  split in its slots. `NormalizeCode` still accepts a hyphen, so a
  habit typed code resolves. Rejected: `ABC-12345` (a second shape to
  document for the one surface).

## Execution rules

- Atomic commit per phase is authorized for this plan; each phase heading
  names its suggested commit message. A commit stages that phase's explicit
  paths only (`git status` first) — never `git add -A` or `git add .`.
- When the last phase lands, the agent stops, reports, and recommends the
  closing commit message with its paths. The standing commit rule resumes.
- No `ALTER`: if a migration edit becomes necessary (D4 option a), edit
  the migration in place. Resetting the development database is
  authorized for this plan.
- No wire change, so no Yaak update and no `rpc:stale` drift expected;
  the final phase confirms it.
- Per-phase validation runs before each commit. Test fixtures follow the
  Dan Brown / Harry Potter list in `.agents/docs/rules.md`; test names stay
  behavioral.
- The plan executes only on the owner's explicit instruction.

## Phases

### Phase 1 — the shared generator and normalizer

Suggested commit: `feat(crypto): letter-digit code generator and normalizer`

`RandomLetterDigitCode` (three letters, five digits, the D2 alphabets,
`crypto/rand` per character) and `NormalizeCode` in `pkg/crypto`, with

Suggested commit: `refactor(identity): emailed codes are three letters and five digits`

delete the length constants and the short/long window, hash through

(length 8, shape `^[A-Z]{3}[0-9]{5}$`, a lowercase-typed code resolves).
Validation: `go test ./modules/identity/... ./modules/devicelogin/... ./internal/transport/...`,

## Explicitly out of scope

- TOTP digits, MFA recovery codes, and every hex token (sessions,
  signup tokens, API keys, device tokens) — not emailed codes.
- A proto `pattern` constraint on the code fields.
- A hyphenated or grouped display of the code.
- Backward compatibility with codes issued before the change.
