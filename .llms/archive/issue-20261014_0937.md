# `vp run` crashes child processes with a native stack overflow in Linux containers

> Archived 2026-10-14 — the finding moved to the roadmap as RI-11
> (`.llms/roadmap/future-improvements.md`): an upstream-gated toolchain
> item, not a trigger-gated issue.

Re-homed from the 2026-10-12 issue (same finding, same trigger) when that
file archived.

- status: open
- plans: —
- trigger: upgrading the `VP_VERSION` pin in `deploy/Dockerfile`, or any future
  `vp run` usage inside a Linux container

## Finding

Inside a Linux container (golang:1.27-trixie, Node 24.21, pnpm 12.9.1 via the
vp shim), `pnpm exec vp run typecheck` aborts with:

```
$ pnpm exec tsc -p packages/webapp --noEmit
thread '<unknown>' (110) has overflowed its stack
fatal runtime error: stack overflow, aborting
```

exit code 134 (SIGABRT), ~0.3s after the child starts. Reproduced on vp CLI
1.0.0 **and** 1.1.0 (`VP_VERSION` pin bump does not help).

## What isolates it

- Direct `pnpm exec tsc -p packages/webapp --noEmit` in the same container: **passes**.
- `LD_PRELOAD=<fspy preload lib> FSPY=1 pnpm exec tsc …` from bash: **passes**
  (fspy inert without `FSPY_PAYLOAD`).
- `vp run` on a trivial task (`echo`) and on a `&&` chain of echoes: **passes**.
- The crash only happens when `vp run` spawns the child with its task-cache
  instrumentation active — it injects `FSPY=1`, `FSPY_PAYLOAD=<blob>`, and
  `LD_PRELOAD=/tmp/fspy/fspy_preload_<hash>.dylib` into every child.
- On macOS the same `vp run typecheck` passes with a cold task cache, so the
  bug is Linux-specific (fspy interceptor × Node 24's thread set is the
  prime suspect; the aborting thread is unnamed/native).

## Why CI masked it until now

The Test workflow restores the **Vite Task cache**, so `vp run typecheck`
replays cached results instead of executing — the bug never fired there. The
Docker build has no task cache, so release runs execute for real and crash.

## Current workaround

`deploy/Dockerfile` runs the typecheck chain directly (the same six `tsc -p …
--noEmit` commands the root `vite.config.ts` `typecheck` task concatenates)
instead of `vp run typecheck`. Keep the two in sync until this is fixed.
Re-verified 2026-10-14: the direct chain stands at
`deploy/Dockerfile:99–104`.

## The parity guard (2026-10-14)

`scripts/check-typecheck-parity.sh` extracts the ordered `tsc -p … --noEmit`
project list from both sides and fails on any drift; the pre-commit hook
runs it on every commit, so the commit that drifts either file is the one
that fails. When a fixed vp ships, restore `vp run typecheck` in the
Dockerfile and delete the guard with this file.

## Next step

Report upstream to vite-plus with this reproduction (Linux container,
`vp run` + fspy preload, Node 24). When a fixed vp ships, restore
`vp run typecheck` in the Dockerfile and close this file.
