## Conventions the next screens must follow

- A page-level wait answers with the shape-matched skeleton composite —
  never a centered Spinner. The Spinner is a control's busy mark only.
- A create/edit form longer than a confirmation rides `SheetContent
  side='right'` with the shared body block; a Dialog is for confirmations,
  show-once secrets, and short single-field inputs. A read-only inspector
  stays a Drawer.
- Every `(app)` page opens with `PageHeader`; every list chain reads
  pending → error (`ListError`) → empty (`Empty`, with the create CTA when
  the opener is in scope) → data. An errored list never renders as empty.
- The skeleton/sheet/error/header composites live in
  `packages/webapp/src/components/` — webapp page conventions, not uilibs
  design. Extending uilibs stays an owner decision.

## Known skips (deliberate, per plan)

- Detail views whose headerLeft carries a DescriptionList or a Link
  breadcrumb (webhook detail, user detail, oidc-client detail) keep their
  hand-rolled headers — `PageHeader` does not express them yet.
- Blocklist, groups, and signup-token empty states carry no CTA: the
  create opener lives in a child dialog's scope; lifting the state is its
  own refactor.
- Charts/telemetry widgets on `/overview` and `/admin/audit` — deferred by
  D3; the index rows stay open.
