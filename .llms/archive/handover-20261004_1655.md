## What the round decided

- **`picture` = the composed public URL under the standard name.** The
  account's picture read-model (the joined `storage_objects` row composed with
  the serving origin) is what the claim answers, and the Go field now carries
  the standard word: `UserView.Picture`, renamed from `AvatarURL` (the owner's
  mid-execution pick — the field the claim reads should not carry two names).
  The wire field saka's own REST API answers stays `avatar_url`: that surface
  is saka's API, not an OIDC claim. The oauthsso feature's `AttributeMapping.
  AvatarURL` and `ExternalIdentity.AvatarURL` are different structs — the RP
  side's mapping vocabulary — and keep their names.
- **`updated_at` = the trigger's stamp, epoch seconds.** §5.1 pins a JSON
  number; `users.updated_at` (trigger `trg_users_updated_at`) is the source,
  read through the one read-model (`UserSchema.UpdatedAt` +
  `UserColumns` + `UserView.UpdatedAt`) — no second query, no migration. A
  NULL stamp (the account no update has touched) falls back to `created_at`:
  its information last changed when it was created, and a profile section
  without the change anchor would hand a relying party nothing to judge
  freshness by. Rejected: omitting when NULL; an RFC 3339 string.
- **`updated_at` joins `protectedClaimKeys`**: the protocol mints it, so an
  operator's custom claim row naming it is dropped at issuance — the same
  defense `picture`, `sub`, and `email` already live under.
- **The preview inherits both.** `preview.go` builds its own profile map
  beside `subjectClaims`'; the round's rule is that the preview's map must
  never name a shape the issuance would not mint, so both carry the same two
  entries under the same conditions.
