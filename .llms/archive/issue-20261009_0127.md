# Login-screen toggles live only in the deployment document, not in the settings catalog

> Archived 2026-10-14 — the owner's pick (2026-10-14, the deployment
> document keeps the toggles) closed the item `wontfix`; the boundary's
> written record is plan-20261014_0930 (D1–D2).

The toggles the login screen gates on — `oidc.enabled`,
`auth.one_time_access_email_as_admin_enabled`,
`auth.one_time_access_email_as_unauthenticated_enabled` — are deployment-file
keys that only `GET /api/configuration` publishes
(`internal/config/publish.go` `Published`). They have no counterpart in the
DB-backed settings catalog (`modules/appconfig/settings.go` `Catalog`), so the
frontend cannot read them through the typed Connect procedure
`SettingsService/ListPublic` (`api/connect/settings.proto`, served by
`modules/appconfig/handler_rpc.go`). The configuration layer therefore reads
the REST document with a hand-maintained shape (`packages/webapp/src/libraries/app-config.ts`)
instead of proto wire types.
