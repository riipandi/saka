## Open notes carried forward

### 1. Verifier does not pin `alg` (decide before a module verifies a token)

`pkg/jwtutils/verifier.go` (~line 87) sets `jws.WithRequireKid(true)` but pins no algorithm:

```go
opts = append(opts, jwt.WithKeySet(v.keySet, jws.WithRequireKid(true)))
```

jwx v3.3.0 has no `WithAllowedAlgorithms`. A token header naming an algorithm the published
set does not carry is therefore not rejected on that basis alone. The intended shape is a
header check in a verifier wrapper, with the allowlist derived from the published keys —
not a hand-kept list that can drift from `auth.jwt_algorithm`.

Related, and the reason this is not urgent yet: the sign/verify path has **zero production
callers**. `jwtutils.NewSigner`, `jwtutils.NewVerifier`, `SigningAlgorithm`, and
`HMACKey()` are exercised only by tests. The publish path (JWKS) is end-to-end verified; the
issue path is not.
