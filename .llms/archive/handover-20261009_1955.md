The plan `.llms/plans/plan-20261009_1826.md` is fully executed: P0–P3 all

## What the migration changed (one screen)

- **codegen** — regenerated from `connectrpc.com/connect/v2/cmd/protoc-gen-connect-go`
  (`buf.gen.yaml`, `scripts/task-development.yml`): unwrapped handler
  signatures, `Register…Handler(server, svc)` instead of `New…Handler` +
  per-path `r.Handle`. `codegen/` is untracked; run `task rpc:generate`
  after a pull.
- **one server, one mount** — `internal/transport/router/rpc.go` builds one
  `*connect.Server` (interceptors `recovery → guard → validate → otel`) and
  serves it with one `connecthttp.Mount`; `connecthttp.NewErrorWriter` from
  the same options answers 404/405/rate-limit in-protocol. The custom JSON
  codec is a v2 stream `Codec`; `WithCodecs` **replaces** the defaults, so
  `connectproto.NewBinaryCodec()` is re-listed beside it.
- **seams** — `RPCModule` is `MountRPC(server *connect.Server)`; claim
  policing reads a scratch server's `Specs()`. Guard is a stream-wrapping
  `ServerInterceptor` enforcing on the first `Receive` (no `WithRecover` in
  v2 — the recovery interceptor re-panics `http.ErrAbortHandler`).
  `BearerAuth` is in-house now: `connectrpc.com/authn` v0.2.0 marshals
  refusals through a v1 `*connect.Error` and cannot see v2 errors — dropped
  (decision D3 revised; the shape and policy are unchanged, refusal via
  `connecthttp.NewErrorWriter`). Caller context + `BearerToken` moved to
  `pkg/jwtutils`.
- **error masking (P2)** — v1 published a plain error's `err.Error()` to the
  wire; v2's `scrubHandlerError` masks it (`unknown`, empty message). The
  audit found the surface already authors coded errors everywhere client
  text is intended; `TestAPlainErrorIsMasked` pins the default. A handler
  wanting a client-visible message must author a `*connect.Error`.

## The harness trap (record so nobody debugs it twice)

`packages/e2e-tests/playwright.config.ts` boots ONE binary per invocation,
picked by `E2E_BUILD_TAG` (`release` default). Release serves the SPA from
the embedded manifest — the session-foundation suite needs that. Debug
serves `/debug/passkey/*` (the ladder needs that) but the SPA document
becomes the dev page proxying the Vite compiler at `127.0.0.1:5173` — with
no `task dev` running, the page hangs at "Loading" with 502s on
`/@vite/client` and friends, and `session-foundation` "fails" for 30 s.
`reuseExistingServer: !CI` plus a lingering `saka serve` on :3000 is the
second trap: an unrelated run's binary answers the reuse probe and the
wrong build serves the suite (a release binary answers the ladder's
`/debug/passkey/enroll` with the 404 envelope). Kill :3000 before any E2E
run and let the harness boot its own server.
