# Plan — OpenID Connect certification readiness

## Objective

Make saka's OIDC provider eligible for OpenID Foundation self-certification:
the **Basic OP**, **Config OP**, **RP-Initiated Logout OP**, and **Back-Channel
Logout OP** conformance profiles rehearsed green against the local OIDF
conformance suite, with the OAuth 2.1 / OIDC Core deltas and the
audit-20261005_1825 recommended fixes closed in code. Design-doc rows this
plan closes: `.llms/auth-design.md` (sessions/logout facts the logout profiles
touch) and the certification-readiness items recorded in
`.llms/audit/audit-20261005_1825.md`.

Flow references (read 2026-10-05): OIDC Core 1.0
(<https://openid.net/specs/openid-connect-core-1_0.html>), RP-Initiated Logout
1.0, Back-Channel Logout 1.0, OAuth 2.1 draft (draft-ietf-oauth-v2-1), RFC 9700,
the OIDF OP testing instructions
(<https://openid.net/certification/connect_op_testing/>), the logout testing
instructions (<https://openid.net/certification/connect_op_logout_testing/>),
and the conformance suite (<https://gitlab.com/openid/conformance-suite>).
Deltas from these references are decisions below, not silent deviations.

## Current state

Verified in the tree, this session:

- The provider serves code+PKCE, PAR, refresh with rotation, client
  credentials, device grant, userinfo, introspection, revocation, end-session,
  back-channel logout — the live E2E (`scripts/oidc-e2e.sh`) answers 33/33.
- PKCE accepts **both** S256 and plain, and the discovery document advertises
  `["S256","plain"]` — `modules/federation/oidc/protocol.go:151`.
- `claims_supported` carries the profile claims only —
  `modules/federation/oidc/protocol.go:420` (`profileClaims`), `sub` and the
  common registered claims absent.
- A client secret an operator supplies is hashed with **unsalted SHA-256** —
  `modules/federation/oidc/secrets.go:178` (`sealSecret`); the verifier
  already accepts PHC strings beside `sha256` hex
  (`modules/federation/oidc/protocol_policy.go`, `verifyClientSecret`).
- The deployment-wide consent ledger read `AllAuthorizedClients` is
  unbounded — `modules/federation/oidc/consent.go:96`.
- The committed `app.config.json` carries the load-test posture:
  `rate_limit.limit` 60000, `auth_limit` 6000 (security defaults are 60/10).
- RP-initiated logout: `logoutPolicy` demands `id_token_hint`, refuses an
  `at+jwt` hint, revokes the subject's grants and tokens in one transaction —
  `modules/federation/oidc/protocol_logout.go`; the end-session redirect and
  the `state` handling ride the library's logout session.
- Back-channel logout: signed `logout+jwt` with `events`, `sid` (when the
  hint named one), 2-minute TTL, delivered through the durable queue —
  `modules/federation/oidc/backchannel.go`; the client carries
  `backchannel_logout_uri` + `backchannel_logout_session_required`
  (`modules/federation/oidc/schema.go`).
- The engine (`luikyv/go-oidc` v0.25.0, module cache) implements **no**
  Session Management 1.0 (no `check_session_iframe`) and **no** front-channel
  logout — both profiles would be greenfield work.
- No product documentation exists for the OIDC provider (`docs/` holds
  api-endpoint, api-response, changelog, contributing, deployment, index); the
  stale `.llms/index.md` reference was removed in the audit.
- Harnesses already committed: `scripts/oidc-e2e.sh` (33 wire checks),
  `scripts/oidc-race-probe.sh` (CAS concurrency).
- Migration `00016_oauth_session_grant_indexes.sql` landed with the audit;
  the dev database was reset and re-initialized this session (admin
  `admin` / `Expecto-Patronum-9`).

## Decisions

- **D1 — 2026-10-05 — Target profiles: Basic OP, Config OP, RP-Initiated
  Logout OP, Back-Channel Logout OP.** Rejected: Implicit/Hybrid/Form Post
  (response types saka does not serve and OAuth 2.1 removes), Dynamic OP
  (registration is closed by design), Session Management OP and Front-Channel
  Logout OP (the engine has no support and Session Management demands an OP
  browser session the auth design refuses).
- **D2 — 2026-10-05 — Rehearsal runs the suite locally in Docker** with a
  TLS-terminating issuer (`task cert:generate` material) inside
  `container/compose-dev.yaml`; the hosted run for the submission package is
  the owner's, after this plan ships. Rejected: hosted-suite-first (flaky,
  not reproducible), hosted-only (no CI-repeatable harness).
- **D3 — 2026-10-05 — The harness drives the real SPA**: Playwright fills the
  sign-in form, reads the email code from Mailpit's API, answers the consent
  page, and watches the logout iframes nothing — no test-only interaction
  path. Rejected: a dedicated automation endpoint (new security surface),
  manual interaction (~100 clicks per run, not reproducible).
- **D4 — 2026-10-05 — Suite clients and the suite account come from a dev
  seeder** (3 clients: two `client_secret_basic`, one `client_secret_post`,
  callback + post-logout + backchannel URIs pointed at the suite's alias; one
  account with a known password), idempotent, dev-invoked. Rejected:
  harness-created clients over the admin RPC (more moving parts in the
  driver).
- **D5 — 2026-10-05 — OAuth 2.1 alignment stays at core**: drop PKCE `plain`,
  complete the metadata, keep exact redirect matching and code-client binding
  (already sound). Rejected: DPoP sender-constrained tokens, PAR-required
  default — neither is a Basic OP prerequisite.
- **D6 — 2026-10-05 — The audit's recommended fixes are adopted into this
  plan** (owner's request): PKCE plain removed, operator-supplied secrets
  hashed PHC instead of unsalted SHA-256, `AllAuthorizedClients` paginated,
  the committed rate limits restored to the security defaults (the load-test
  override moves to untracked local configuration), `claims_supported`
  completed, and the `docs/oidc-provider/` product page written.
- **D7 — 2026-10-05 — No backward compatibility**: early stage, so the PKCE
  and secret-shape changes break no clients; migration edits happen **in
  place** (no ALTER migrations), the dev database may be reset at any phase,
  and re-initialization re-provisions seed + keys.
- **D8 — 2026-10-05 — `at_hash` on the code-flow ID token is attempt-then-
  record**: the engine emits it when the issuance options carry the access
  token (`internal/token/token.go:175`); if the code-flow path already passes
  it, the token simply carries it — if the engine's code flow does not, the
  deviation is recorded here and in the endpoint reference (OIDC Core §3.1.3.6
  makes it optional) rather than forked.
- **D9 — 2026-10-05 — The OP browser-session marker exists** (phase 4's
  finding): `prompt=none` semantics demand a browser-side answer the design's
  "no browser session" never provided, and the Basic OP profile tests both
  sides of it. The marker is the minimal thing: an HttpOnly cookie naming
  the completed authentication session, read by `prompt=none` and by the
  `max_age` resume, never by the SPA. Session Management's iframes stay out
  of scope (D1).
- **D10 — 2026-10-05 — JAR by value is supported** (phase 4's finding): the
  unsigned request object the Basic OP profile sends plus ES256 for a
  client that registers a key set; the profile's state and nonce ride the
  object. The Config OP profile additionally requires RS256 named in the
  discovery document — the seed provisions the RSA pair beside the primary
  key, and the JWKS publishes both.

## Execution rules

- **Atomic commit per phase is authorized**: each phase lands as its own
  commit, limited to that phase's files, after the phase's validation runs
  green. Each phase heading below names its suggested commit message.
- **Migration rule**: edit migration files in place (no ALTER-style follow-up
  migrations); `task db:reset -- --up`-equivalent re-apply plus
  `initialize` is authorized at any phase, and the harness may reset freely.
- **Yaak updates ride the same change** as the contract they expose — though
  no phase plans a new procedure.
- **Docs sync is the closing phase's job**: endpoint reference, audit
  cross-reference, auth-design checkboxes, the product doc, and the handover.
- Per-phase validation runs before each commit; a red validation blocks the
  commit, and the blocked phase stays open with the failure named.
- The plan executes only on the owner's explicit instruction.

`feat(oidc): close the OAuth 2.1 and audit-recommended protocol gaps`

- Complete `claims_supported` (`sub`, the registered claims, the Standard
  Claims the surface answers).
- `suppliedSecret` hashes PHC (password hasher); random mints unchanged.
- Paginate `AllAuthorizedClients` (page/limit, metadata on the wire).
- Restore `app.config.json` rate limits to 60/10; document the untracked
  load-test override.

  per D8.

  `task lint`, `scripts/oidc-e2e.sh` (extended with a plain-PKCE refusal and
  the `sub` claims check), release-binary serve probe.

`fix(oidc): carry the RP-initiated and back-channel logout details the suite tests`

## Explicitly out of scope

- Session Management OP and Front-Channel Logout OP (D1; engine lacks them,
  Session Management contradicts the no-browser-session design).
- Implicit, Hybrid, and Form Post OP profiles (OAuth 2.1 removes implicit;
  saka serves `response_type=code` alone).
- Dynamic OP (registration stays closed; the mounted `/oidc/register`
  refusal is the final shape).

- FAPI profiles of any generation.
- The hosted-suite submission run itself — the runbook (phase 6) hands it to
  the owner; fees and the certification mail are the owner's.
- Any change to the sign-in surface beyond what driving it demands.
