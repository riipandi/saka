# lazyPublisher.CreateSystemNotice silently drops the notice when the notification service is absent

- status: resolved (plan-20261014_0915.md, phase 1 — commit `7f99fbf4`)
- plans: plan-20261014_0604.md (the 2026-practices adoption; found by tier A
  of the error-context sweep, phase 4) · plan-20261014_0915.md (the fix)

## Finding

`internal/registry/infrastructure.go:59-64` — `lazyPublisher.CreateSystemNotice`
resolves `*notification.Service` through `do.Invoke` and answers
`if err != nil || service == nil { return err }`. When the invocation fails the
error travels; when it returns `nil` with a `nil` service the method returns
`nil` — the notice vanishes and the caller (a job's success path) reports
success.

The two sibling seams in the same file behave differently and **document** the
difference: `lazyScimSyncer.SyncAll` and `lazyOAuthOffboarder.OffboardPass`
explicitly `return nil` on a nil service with the comment "the pass is skipped
rather than failed". `lazyPublisher` carries no such comment, so its silent
drop reads as an accident of the combined condition, not a decision.

## Impact

A system notice (sign-up attempt, user-locked, passkey notices — the jobs that
ride the publisher) is lost without a log line whenever the notification area
is not wired into the container, while every other lazy seam in the file
either fails loudly or names its skip.

## Resolution (2026-10-14)

The plan's verification sharpened the finding: the `(nil, nil)` branch is
unreachable (do v2 answers a missing service with an error, and the
notification provider never returns a nil service), so the real defect was
the opposite — a container without the area made the upload-finished task
fail and dead-letter, against the contract the `NoticePublisher` seam itself
documents. The fix skips the advisory notice on the do not-found sentinels,
travels on any other invocation error (the retry budget's job), keeps the
defensive nil-service skip in the siblings' shape, and rewrites the garbled
type comment. The skip and travel paths are pinned in
`internal/registry/lazy_publisher_test.go`; the delivered path stays pinned
by the upload-finished job's stub tests. Trigger consumed.
