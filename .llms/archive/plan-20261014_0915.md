# Close the lazy-publisher seam's contract gap (`issue-20261014_0730`)

## Objective

`lazyPublisher.CreateSystemNotice` contradicts the contract its own
consumer documents: when the notification area is absent from the
container, the upload-finished task fails and dead-letters where the
seam's contract says the notice is skipped. The plan aligns the seam with
its contract, pins all three resolution paths in tests, and retires
`issue-20261014_0730.md`.

## Current state (verified in the tree, 2026-10-14)

- **The implementation fails where the contract says skip.**
  `internal/registry/infrastructure.go:59-64` — the combined condition
  `if err != nil || service == nil { return err }` returns the invocation
  error, and a container without the notification area answers exactly
  that: samber/do v2.1.0 resolves a missing service to a wrapped
  `do.ErrServiceNotFound` (`invoke.go:43,52,99`), so the seam returns the
  error and the task fails. The consumer's contract is written on the
  other side of the seam — `internal/jobs/upload_finished_job.go:44-48`:
  *"a nil publisher is a deployment without the notification area — the
  notice is skipped rather than failed"* — and the job's whole skip
  philosophy is consistent with it: an unaddressable owner skips
  (`upload_finished_job_test.go:47-70`), a queue-less container skips at
  the enqueuer (`:72-89`), and only a publisher that refuses mid-call is
  retried (`:62-69`).
- **The failure mode is a dead letter on a success path.** The
  `upload_finished` task's config carries `MaxAttempts: 5` with a
  one-minute backoff (`upload_finished_job.go:35-42`) — an absent
  notification area walks every successful upload's notice into the dead
  letters, five minutes apart, in a deployment that deliberately ships
  without the area.
- **The `(nil, nil)` branch is unreachable.** The notification area's
  provider (`modules/notification/module.go:36-53`) is a `do.Lazy` that
  either returns a built service or an error; do v2 answers a missing
  service with an error, never `(nil, nil)`. The branch is defensive
  dead code — and it is the branch the issue originally read as the
  "silent drop".
- **The siblings already carry the right shape.**
  `lazyScimSyncer.SyncAll` (`infrastructure.go:76-85`) and
  `lazyOAuthOffboarder.OffboardPass` (`:97-107`) separate the two cases:
  the invocation error travels, an absent service answers nil, and the
  type comment says so ("the pass is skipped rather than failed").
- **The publisher's own type comment is garbled.**
  `infrastructure.go:47-52` — *"answers the failure the skip falls back
  to, the notice being advisory"* — describes neither behavior the code
  has; it is prose the comment rules would reject on sight.
- **The notice is advisory and the surface is one caller.**
  `CreateSystemNotice` is consumed only through the
  `NoticePublisher` seam (`upload_finished_job.go:50,69`); the task's own
  comment names the notice advisory (`:32-34`). The production `serve`
  container always registers the notification area
  (`internal/registry/modules.go:66`), so the absent case exists only in
  a consumer container or a test — exactly the deployments the skip is
  written for.
- **No registry test covers any lazy seam's resolution paths.**
  `internal/registry/compose_test.go` exercises the container build; the
  lazy seams' absent/present/failing paths are untested.

## Decisions

- **D1 (2026-10-14): an absent area skips; a real resolution failure
  travels.** The seam distinguishes the two with the do sentinels —
  `errors.Is(err, do.ErrServiceNotFound)` (and `ErrServiceNotMatch`) means
  the container does not hold the area, and the notice is skipped with
  nil; any other error means the area is present but its construction
  failed, and that error travels so the retry budget works on a real
  outage. Rejected: skipping on *any* error — a provider that fails
  mid-construction is an outage the queue's attempts exist for, and the
  failing-publisher test (`upload_finished_job_test.go:62-69`) pins that
  shape. Rejected: keeping the fail-on-absent behavior — it contradicts
  the seam's own documented contract and dead-letters the upload's
  success path; the upload is the fact the queue carries, the notice is
  the bell that rings after it.
- **D2 (2026-10-14): the unreachable `(nil, nil)` branch stays, in the
  siblings' shape.** The skip is defensive, and the file's convention is
  that all three lazy seams read alike — a reviewer who has read one has
  read all three. Rejected: deleting the nil check (a one-line asymmetry
  in a file whose value is its uniformity) and deleting the siblings'
  checks (out of scope — they are correct as they stand).

## Explicitly out of scope

- **The siblings' shape** — `lazyScimSyncer` and `lazyOAuthOffboarder`
  already separate the error from the skip; only the publisher is
  rewritten.
- **New notice types or new callers of `CreateSystemNotice`** — the seam
  serves the upload-finished notice alone; a second consumer reopens the
  contract, not this plan.
- **The do-container's nil-provider hardening** — do v2 refuses a
  `(nil, nil)` provider at construction; no code is added for a state
  the library cannot produce.
- **A wire change** — the seam is process-internal; no procedure, route,
  email, or audit event is touched, so no Yaak row is owed.
