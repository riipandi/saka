# Adopting the 2026 Go and PostgreSQL practices the tree is missing

## Objective

Two articles read on 2026-10-14 — Anshu Singhal, "I Scanned 500+ Golang
Projects: Here Are the 7 Blunders Everyone Keeps Making" (Medium, read via
freedium-mirror) and EdgyCorner, "PostgreSQL Like a Pro: The Tricks That
Actually Matter in 2026" (Medium, read via freedium-mirror). The plan adopts
the practices the tree is measurably missing, records the contracts that keep
them missing no more, and refuses the ones that do not fit — with the
owner's own emphasis carried: the context-free error returns are the tree's
largest real debt, so the sweep owns four phases, not a token audit.

## Current state (verified in the tree, 2026-10-14)

- **Context-free errors are the largest finding.** 723 naked error returns
  across production code: `modules` 281, `internal` 150, `framework` 131,
  `cmd` 150, `pkg` 11. The heavy packages: `modules/identity` 127,
  `modules/federation` 105, `internal/jobs` 61, `internal/database` 48,
  `internal/registry` 20, `internal/transport` 17. The repositories already
  carry the breadcrumb convention — 1,012 `fmt.Errorf` wraps, shaped
  `"session: list: %w"` (`modules/identity/session/repository.go:293`) — so
  the debt is not the absence of a convention but its uneven application.
- **The account search's email arm has no index.**
  `modules/identity/user/repository.go:139-149` filters `ListUsers` (and its
  count, lines 180-188) by `ILIKE %term%` over username, email, and display
  name — "the columns the indexes exist for", the comment claims
  (repository.go:140-141). The indexes exist for two of the three columns:
  `idx_users_username` and `idx_users_display_name` carry
  `gin_trgm_ops` (`internal/database/migrations/00004_create_identity_tables.sql:51-52`);
  the email column — `TEXT NOT NULL UNIQUE` (migration 00004:11) — has none,
  so the three-arm OR cannot compose a full BitmapOr and the claim in the
  comment is false today.
- **The storage write path reads through an unrooted join.** `List` opens
  the bucket subtree through `os.OpenRoot` (`framework/storage/storage_fs.go:106`),
  but `Get` opens `os.Open(s.path(...))` (line 45), `Put` writes the same
  join (line 66), and `Delete` removes it (line 93) — `path()` is the bare
  `filepath.Join(s.root, uploadsDir, bucket, filepath.FromSlash(key))`
  (line 154). The key validation contract (`framework/storage/storage.go:113-123`
  refuses `.`/`..`/absolute/empty segments with `ErrInvalidKey`) is the
  primary fence; `os.Root` on the three mutating/reading calls is the second
  one, and the list side already has it.
- **Six `go func()` sites in production code** —
  `framework/middleware/unbounded.go:66`, `framework/logger/logger.go:342`,
  `framework/health/health.go:294,343`, `framework/queue/dispatcher.go:208`,
  `cmd/serve.go:127`. Prior audits judged the framework's goroutine
  discipline sound (audit-20261005_0940's concurrency section), so the
  expected verdict is confirmation — but the six sites deserve a named pass,
  not an inherited one.
- **The stdlib is already largely adopted.** `slices` is imported by 35
  production files; `os.Root` is in `List`; the tool directive carries
  `deadcode` (go.mod, the 2026-10-14 commit `57778247`); routing stays chi by
  the recorded decision. One hand-rolled scan-flag loop surfaced in the
  checks: `modules/federation/oidc/secrets.go:151` (`found := false` + a
  range loop).
- **PostgreSQL 18 is the floor.** The testcontainers image is
  `docker.io/postgres:18-alpine` (`pkg/testutils/postgres.go:25`), so the
  AIO subsystem rides the version automatically; PG 19's `REPACK` and the
  planner's hypothetical-index suggestions are out until the images move.
  `pg_trgm` is already created (migration `00001:10`) and GIN trigram indexes
  serve the search surfaces that have them.
- **No `SELECT *` in production code** — the grep over `modules/`,
  `internal/`, `framework/`, `pkg/` answers nothing; the repositories name
  their columns (`sessionColumns`, `UserColumns`, …). The blunder is
  structurally absent.
- **The compose PG service is commented out** (`container/compose.yaml:49`),
  so the pg_stat_statements posture lands in the test containers and the
  documentation, not in a deployment compose file.

## Decisions

- **D1 (2026-10-14): the error-context contract is "one breadcrumb per
  boundary".** Each package's public methods name the operation once — the
  existing repository convention (`"session: list: %w"`) is the shape — and
  inside a package a `return err` that crosses no boundary is correct Go,
  not a defect. The sweep wraps where a boundary is crossed without a
  breadcrumb: into a log line (jobs, cmd), into a response (transport,
  registry), across a package seam (the modules), or up a call chain whose
  intermediate frames name nothing. Rejected: wrapping every call site (the
  article's literal fix) — a five-frame chain of prefixes
  (`cmd: serve: registry: identity: user: query: ...`) buries the message
  it exists to clarify. `%w` keeps every sentinel (`errors.Is`/`errors.As`
  callers unaffected), so the sweep changes messages only, never control
  flow.
- **D2 (2026-10-14): the sweep is tiered by log visibility, biggest first.**
  Tier A is what an operator reads at 2 AM (`cmd`, `internal/jobs`,
  `internal/registry`, `internal/transport`); tier B the identity modules
  and the small ones; tier C federation; tier D the plumbing (`framework`,
  `internal/database`, `pkg`) where deep pass-through is often the right
  answer and each site earns its wrap. Tier D may end with a "no change"
  verdict per file — that is a result, not a failure.
- **D3 (2026-10-14): the storage paths route through `os.Root` as
  defense-in-depth.** The validation contract stays the primary fence and
  the FS layer gains the rooted fence below it — a future caller that
  bypasses validation cannot escape the root. Rejected: replacing the
  validation with the root alone — the validation is the API contract the
  callers see (`ErrInvalidKey`), the root is an implementation fence.
- **D4 (2026-10-14): the email arm gets its trigram index.** The search
  filters three columns and the plan's claim is one index — the smallest
  honest fix for a comment the tree does not honor yet.
- **D5 (2026-10-14): keyset pagination is refused.** Every list rides the
  page/offset wire contract the Connect procedures and `usePaginatedList`
  share (`ListMetadata`, the shared `LIST_DEFAULT_LIMIT`/`LIST_MAX_LIMIT`);
  the admin surfaces paginate shallowly by practice, and a cursor protocol
  would rewrite every procedure's proto and the SPA's pager for a cost the
  tree has not paid yet. Recorded for revisit: a list that measurably pays
  the deep-page cost reopens this.
- **D6 (2026-10-14): partitioning, `REPACK`, and the PG 19 planner
  suggestions wait for the images.** The containers run PG 18 (`pkg/testutils/postgres.go:25`)
  and no table is near partitioning scale; the AIO gains ride 18 without
  code. The vacuum/dead-tuple and index-usage queries land in the
  observability document as the maintenance runbook instead of in code.
- **D7 (2026-10-14): `pg_stat_statements` is a dev and test capability, not
  a migration.** A `CREATE EXTENSION` migration would fail any deployment
  whose PostgreSQL lacks the preload; instead the test container starts with
  `shared_preload_libraries=pg_stat_statements` (and creates the extension),
  and the runbook documents the deployment-side enablement. Rejected: a
  migration (the failure mode above).
- **D8 (2026-10-14): the interface and pointer blunders are recorded, not
  swept.** The tree already follows the discipline — consumer-shaped seams
  (`session.Issuer`, the `SignupTokenSweeper` seam), struct returns over
  interface factories, repositories returning slices of structs — and a
  blanket rewrite would churn the tree without a finding. `rules.md` states
  the discipline as the rule new code is judged by.

## Execution rules

- The plan runs only on the owner's explicit instruction; it never starts,
  resumes, or continues on its own.
- Atomic commit per phase is authorized; self-commits during this plan's
  working session are allowed; each phase's heading names its commit
  message; each commit is limited to that phase's files.
- No backward compatibility, no legacy shims. Migrations are edited in
  place — no ALTER; the development database may be reset and reseeded
  during the work.
- Per-phase validation runs before each phase's commit; heavy suites
  (`go test ./...`) run sequentially, never concurrent with another suite.
- The error sweep never changes control flow: a wrapped message keeps the
  sentinel, and a test that matched a message prefix follows the message.
- The standing commit rule resumes when the plan completes: the agent stops,
  reports the outcome, and recommends the closing commit message (the plan's
  frontmatter flip to `done` is the owner's approval to execute, recorded as
  the working protocol).
- Phases 10 owns the docs sync; a shipped surface whose doc row lags is a
  defect of that phase, not a follow-up.
