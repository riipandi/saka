## What the round decided (deltas from Clerk recorded)

- **Empty mapping field = the default claim name**; an explicit mapping names
  THE claim — a provider that does not answer it leaves the field empty, never
  silently reading the standard claim behind the mapping's back. This is
  sharper than Clerk's "empty = don't set" and the handover-worthy relaxation
  of the old behavior: a connection that mapped `email` to `mail` no longer
  reads `email` when `mail` is missing.
- **Custom attributes are account-level** — `users.custom_attributes` JSONB
  (the `publicMetadata` analog), merged read-merge-write under `FOR UPDATE`
  inside the resolution transaction. Values store as they arrived (scalars and
  arrays of scalars); blanks drop, objects refuse per claim, never a sign-in
  failure. There is no multi-value toggle and no "don't set" sentinel.
- **The profile refresh rides a seam the user module owns**
  (`ApplyProviderProfile` / `MergeCustomAttributes` / `RefreshProviderPicture`,
  the `profileApplier` interface wired `WithProfiles` post-construction).
  Names and custom attributes apply inside the resolution transaction; the
  avatar downloads over the outbound fetcher **beside** it — the picture
  pipeline (sniff, stage, sync, manifest) is the storage engine's own and not
  a transaction's member — capped at 4 MiB, every failure logged, the stored
  picture kept, the sign-in never failed.
- **Username is JIT-only**: the mapped claim (cleaned to `[a-z0-9_]`, 29
  characters) names the account once at creation; a taken candidate retries
  with a `_N` suffix. The suffix loop turned out to have been broken from the
  start — one unique violation poisoned the transaction the retry ran in — and
  now retries under a `SAVEPOINT jit_username_attempt`. The mapped username
  never rewrites on later sign-ins.
- The `require_names` pause keeps its shape: a refresh that names nobody does
  not re-open the pause on an account that already carries names.

## The E2E ladder, rebuilt

The restructure commit `4e6a3d3f` had deleted `tools/e2e-oauthsso/`; the owner
picked a full rebuild. The ladder is `tools/e2e-oauthsso/ladder.mjs` — Node
stdlib (`fetch`, `node:crypto`, `node:child_process`) plus `otpauth` (the
owner's pick) for the TOTP answers, split into `lib/` (rpc, walk, totp,
mailpit, sql, admin, state, check) and `steps/` (preclean, basics, guard,
mapping, cleanup). It passed **36/36** over `build/release/saka`:

- The old 24 (updated from `tango.*` to `saka.*` service names and the
  `X-Saka-Reauthentication` header), self-contained now: the admin credential
  is minted by the ladder's own `AuthService/SignIn` (seeded
  `admin@example.com` / `@dmin123`), and the three custom connections it walks
  are created when absent and deleted by the cleanup step.
- The new probes (9–12): a mapped-subject JIT + binding, the mapped username
  as the account's handle, `email_verified_default=true` steering a provider
  that answers no verified claim, the mapping rewrite followed by a second
  sign-in refreshing the names and the custom attributes (read fresh via
  `ListUsers`; the token's user view is the mint's snapshot and can trail the
  row by one sign-in — noted as a nuance, not a defect), the username
  surviving, and the avatar the mapping names landing on the account.

Run environment (the handover records it so the next round does not rediscover
it): the compose stack lives under **two project names** — the `saka-*`
containers belong to the old `tango` checkout's compose file and hold the dev
database on 5432; the `container-*` ones are this repo's. The stale mailpit
published no ports, so the ladder's mailpit now runs from this repo's compose
(`container-mailpit-1`). `container/mock-oauth2.json` gained the `custom`
issuerId whose branches answer nonstandard claims (`user_uuid`, `mail`,
`mail_verified`, `handle`, `second_given`, `dept`, `house`, `photo`); the
`noverify-*` branch answers none. `container/nginx-proxy.conf` serves
`container/mock-assets/minerva.png` at `/mock-avatar/` on the 3220 TLS front
(mounted into the nginx container by `compose-dev.yaml`). The ladder runs with
`node --use-system-ca` (the mkcert certificate is not in Node's own bundle)
and the server under a throwaway config that raises both rate-limit budgets.
