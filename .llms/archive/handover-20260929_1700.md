## Confirmed / high-confidence audit candidates

1. **OIDC authorization ignores configured allowed-group roll.** `modules/federation/oidc/protocol_policy.go:100–143` loads the client but does not test account membership against `oidc_clients_allowed_user_groups`. `SetAllowedGroups` explicitly documents that an enabled restriction with an empty set admits nobody (`service.go:369–372`), while `ListMyClients` only filters the client catalogue. Add enforcement to every authorize and device approval completion path, then tests for restricted/no-group and mismatched account.
2. **SCIM URL path composition is suspect but needs confirmation.** `modules/federation/scimsync/sync.go:262–273,348–355` calls `path.Join(strings.TrimRight(endpoint.Path, "/"), p)` where `p` begins with `/Users` or `/Groups`. Existing test expected URLs include `/scim/v2/Users` and have passed, so do not accept the previous subagent assertion without a small direct Go probe/test. The implementation likely preserves base path as Go `path.Join` differs from Python `os.path.join`.
3. **Custom claim keys may overwrite protocol claims.** Token assembly writes custom claims after standard profile fields in `protocol.go:352–363`; preview merges them in `preview.go:140–146`. No validation for reserved key surfaced in `customclaim`. Confirm valid policy and implement key protection only if architecture/product scope allows it; add conflict tests.
4. **Device grant one-time token exchange race.** OIDC library `go-oidc` v0.25.0 performs device code consumed-check, then `SaveGrant`, then token issuance without transaction/CAS. Context7 docs retrieval for `/luikyv/go-oidc` corroborates this. Saka `grantStore.GrantByDeviceCode` / `SaveGrant` (`protocol_storage.go:119–159,170–188`) performs read and pointer deletion separately. A fix likely needs an atomic claim/CAS integrated with token issuance; check exact library API and compatibility before design.
5. **Expired OIDC session storage growth.** Protocol storage reads active rows without checking `expires_at` (`protocol_storage.go:80–92`), and no cleanup for `oauth_sessions` was found yet. Verify jobs and migration indexes before proposing lifecycle changes.
6. **Device-login limit appears unused.** `maxPendingRequests=8` at `modules/devicelogin/schema.go:21`, `CountLiveForToken` in repository at `repository.go:139–150`, but `Create` does not enforce it (`service.go:65–85`). This is likely a meaningful DoS/resource guard omission.
7. **Device user-code approval binding concern.** Prior audit claimed user-code session not bound to approving identity; investigate provider policy and library semantics carefully. In RFC 8628, user explicitly inputs/validates user_code then separately authenticates/approves. Saka has a token-to-session lookup by user code; determine if callback user_code flow is actually retained and whether session ID callback is sufficient.
8. **SCIM remote response hardening/perf.** Validate SCIM remote item IDs before delete, pagination forward-progress, build externalId maps instead of repeated linear scans. A claimed destructive-empty snapshot concern is not confirmed: no allowed groups + restriction intentionally means no visible users/groups and syncing by deletion may implement deprovisioning correctly.

## Pocket ID upstream comparison

Latest stable found as of 2026-09-29 is **v2.14.0**, published 2026-08-18. Sources:

- Release notes: <https://github.com/pocket-id/pocket-id/releases/tag/v2.14.0>
- SCIM docs: <https://pocket-id.org/docs/configuration/scim>
- RFC 8628: <https://datatracker.ietf.org/doc/html/rfc8628>
- Pocket ID DeepWiki repository `pocket-id/pocket-id`, pages 4.2 and 4.3 (use with caution; answers conflict on some endpoint details).

v2.14.0 notes multi-client secrets, RFC 8414 `/.well-known/oauth-authorization-server`, CIMD API auto-grants, and SCIM sync actor migration. SCIM docs say unrestricted clients sync all users/groups; restricted client syncs only assigned members/groups; hourly and five-minute debounce; manual sync. Saka implements outbound SCIM with its own RPC paths/one-time sealed token response. Pocket ID has `POST /api/scim/service-provider` and per-client service-provider route; the Yaak requests mark this intentionally different.

Saka's `.llms/endpoint-reference.md` stale header says protocol endpoints/consent/CIMD are planned even though rows below mark them implemented. Active Saka OIDC endpoints include `/oidc/authorize`, `/oidc/token`, `/oidc/userinfo`, `/oidc/end-session`, `/oidc/introspect`, `/oidc/par`, `/oidc/device_authorization`, `/oidc/device`, interactions, OpenID discovery, and `/oidc/clients/{id}/logo`; RFC 8414 discovery metadata path is not mounted. Saka scopes currently `openid profile email groups`; no `offline_access`. No client credentials grant; CIMD filters it out intentionally.
