## What the audit covered

The audit request was `cmd/`, `database/`, `internal/`, `modules/identity/jwks/` — race
conditions, leaks, defects, vulnerabilities. Four defects were found and are now fixed.
These areas were checked and came back clean, so a later session need not re-walk them:

- **SQL injection** — `database/` consistently uses `pgx.Identifier{}.Sanitize()` for
  identifiers and `$n` for values; `Table.Qualified()` sanitises. Raw SQL is confined to
  `database/` maintenance tooling, as `AGENTS.md` requires.
- **Goroutine lifetime** — health check results channel is buffered `len(due)`, the done
  channel is buffered 1, `runCheckFunc` recovers panics. No leak path found.
- **`internal/cache/cache_memory.go`** — per-shard `RWMutex`, collision slots store the key
  and verify bytes, monotonic clock, `nextChunk` clears both `m` and `collisions`. No
  corruption path.
- **`internal/logger/async.go`** — `Close()` idempotent via `sync.Once`, bounded drain,
  `closeSink` bounded by context.
- **`internal/storage/watcher.go`** — timers touched only from the loop goroutine; the
  "no lock" claim in its comment holds.
- **`modules/identity/jwks/repository.go`** — the private key column is never selected;
  `rows.Close()` and `rows.Err()` are both handled.
