(`.llms/plans/plan-20261004_1800.md`, phases 1–11 shipped, plus the transport
reorganization `f7d01be5`): the 18 `framework/` packages, the config split, the

## Findings fixed

### Memory leak: the tus per-upload lock map never shrank

`framework/storage/tus_handler.go` kept a `sync.Map` of upload locks and never
deleted entries: every `bucket/key` ever uploaded left a permanent mutex —
unbounded growth on a long-lived server. The fix replaces the bare mutex with
a refcounted entry (`uploadLock{mu, refs}`) that the last holder deletes while
still holding the mutex. The delete-under-lock and the stale-grab re-check are
what make it race-free: an appender that took the entry before the delete
either finishes under it or finds it swapped out and takes the new one — two
chunks for one file still cannot interleave. Pinned by
`framework/storage/tus_locks_test.go`: the entry lifecycle, and eight
concurrent uploaders with an inside-the-critical-section counter, under
`-race`.

### Stale legacy paths in tree documentation

The root `README.md` linked five engine READMEs at their pre-extraction
`internal/…` paths; the queue and scheduler READMEs still claimed their schema
was owned by `internal/database/migrations/00008_create_scheduler_tables.sql`
(the file no longer exists — the sets are owned by the packages since phase
10); `framework/datastore/README.md` pointed at `database.NewMigrator` and
`framework/middleware/requestid.go` at `pkg/responder`. All corrected to the
`framework/…` paths and the owned-set story.

### Unnecessary conversions (dead weight, no behavior change)

`goidc.SignatureAlgorithm(algs[0])` where `algs` is already the typed slice
(`modules/federation/oidc/protocol.go`), `int64(tag.RowsAffected())` where the
driver already answers an int64 (`modules/identity/onetimeaccess`), a
conversion to a type alias of its own operand (`modules/identity/signin`),
and a `(*bool)` conversion of an already-`*bool` proto field
(`modules/webhook`). Each package's tests re-run green.

## Vulnerability reviewed and deferred by decision

**GO-2026-6615** — `go.opentelemetry.io/otel/sdk/log`'s `BatchProcessor`
busy-spins a CPU while its export buffer is full (a collector unreachable
long enough, with log volume outrunning the drain). Our code is affected:
`framework/logger/otlp.go` builds the batch processor with
`otel.queue.max_size` bounding the queue. The fix is in `sdk/log` v0.21.0,
but its `otel/log` API no longer compiles the
`go.loglayer.dev/transports/otellog` transport we use (and the v1.47.0 family
breaks it the same way); closing it means replacing that transport with an
in-house adapter — deliberately deferred. Exposure is bounded: a full queue
means the collector is already down, the failure mode is CPU burn on an
already-degraded run, and the memory side is capped. Recorded in
`.llms/architecture.md`'s `otel` section. The other two findings
(GO-2026-6443 grpc, GO-2026-5932 openpgp) are not reachable from our code.

## Reviewed and found sound

**Circular dependencies.** None. `go list -deps` per framework package shows
no framework package importing `internal/**` or `modules/**` — `_test.go`
files included (the depguard rule holds). The transport split composes
one-way: `router → {handler, middleware, devtools}`; neither the handler, the
middleware, nor the devtools imports the router, and nothing imports the root
`transport` package back.

**Concurrency.** The queue dispatcher's generational lifecycle (drain of the
worker-token pool across restarts, the fetcher's deferred channel close
joined on its own WaitGroup before a rebuild, the task context released only
after the drain wait) is correct under the race detector. The scheduler's
tick claim (`SELECT … FOR UPDATE` on a `UNIQUE`-indexed name, `next_due`
advanced from the old value) makes replica races a no-op. The memory cache's
sharded ring verifies entry keys before answering, so hash collisions cannot
corrupt. The async log transport never drops and drains on close. The
bundler's release fragment resolves under `sync.Once`. All clean under
`-race`.

**Resource lifecycles.** The fetcher always closes or buffers the response
body (resty buffers by default; the raw path closes explicitly, size-capped
with `io.LimitReader`). Migration commands open one single-connection handle
shared by all four set providers, closed by one function. Every
ticker/channel in the queue and scheduler is stopped or closed on its exit
path. `time.After` in the SCIM debounce is bounded by the task's own
lifetime. `bodyclose`/`sqlclosecheck`/`noctx` report nothing in production
code.

**Database shape.** The framework-owned sets' indexes match their queries:
`idx_queue_tasks_fetch` is the claim's partial-ordered index, the archive
carries the expiry and dead-letter partial indexes the admin reads use, and
the scheduler's `UNIQUE(name)` is what the `FOR UPDATE` claim and every
reseed path hit. `audit_logs` carries the created-at/event/user_id indexes
the reader's facets use. Nothing scanned sequentially that an index already
answers.

**Deliberate duplication.** The five-line `instrumentName` helper exists once
per engine (fetcher, queue, scheduler, storage, middleware's inline variant)
rather than in a shared telemetry package — each engine composes without a
common dependency, which is the extraction's own rule. `Config` (1.3 KB) is
passed by value at composition boundaries only — not a hot path.

**Secrets and hygiene.** `gosec` clean; crypto material flows through
`secretKeys` with the `Redacted`/`Masked` renderings pinned by tests;
`crypto/rand` where randomness reaches a wire format; the identity sweep
finds no application vocabulary inside `framework/`.

## Deferred, with reasons

- The otel upgrade above — the only open security item, accepted by decision.
- `codegen/proto/…` and `api/connect/common.proto` still mention
  `pkg/responder` in a file-top comment; correcting it costs a regeneration
  cycle for prose inside a generated file, so it stays until the next spec
  change regenerates it anyway.
- A shared telemetry-naming package if a sixth engine ever needs the helper —
  not while the count stays at five.
