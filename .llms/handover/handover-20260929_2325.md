## Bugs the E2E run caught (both fixed, both in the closing commits)

1. **The RFC 8414 alias answered 401.** The guard's REST rules table
   named the openid-configuration path but never the alias. Added
   `/.well-known/oauth-authorization-server` as `Public` in
   `internal/guard/rules.go`.
2. **Refresh rotation left the retired token alive.** The rotation
   saved the grant with the new token but never deleted the old
   pointer row, so a replayed token kept minting tokens. The fix (in
   `modules/federation/oidc/grant_cas.go` and `protocol_storage.go`)
   records the presented refresh token's hash when the grant loads
   through a refresh pointer, and the save deletes that pointer as the
   replacement lands — a replay finds no row.
3. (Phase-7 fallout, fixed in the same run) `SaveGrant` stripped
   `AuthCodeExpiresAt` along with the auth code, zeroing the code's
   deadline in the stored document; the token endpoint then refused
   every code as expired. Only the auth code itself is stripped now.
   The store also keeps the live refresh token in the document — the
   token response reads it from there — while the pointer rows carry
   only hashes. `provider.WithAuthCodeLifetime(60)` is pinned
   explicitly.
