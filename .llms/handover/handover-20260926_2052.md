## Durable facts a fresh agent must not relearn the hard way

All also stored in memory (searchable):

- Wire-form idiom per feature is settled: typed id in the feature's `schema.go`,
  scan-once in the repository, `UUIDFromWire` at the request boundary, `FormatID` at
  the wire. Applied to `user_`, `ugrp_`, `sess_`.
- `typeid` v1.3.0: `TypeID.UUID()` returns a **string** (hex); `UUIDBytes()` +
  `uuid.UUID(bytes)` for the real UUID. Never hand-roll a TypeID encoder.
- `TypeID.Scan/Value` supports TEXT only — uuid columns + explicit conversion is
  correct, not an oversight.
- Yaak CLI: `request update --json '<payload with "id" inside>'` (the request id goes
  INSIDE the JSON; positional JSON shorthand is rejected). Backticks in descriptions
  get eaten by `bash -c` — pass list-args via python subprocess.
- The transport's session liveness is the SESSION SURFACE's own gate, not the guard:
  a fake SessionID in a transport test must be a real seeded row's TypeID string.
- `audit_logs.resource_id`/`user_id` are UUID columns — never write a `ugrp_`/`user_`
  TypeID into them; the recorder's `UUID()`-string form is what session/group writers use.
- Guard `ContractProcedures()` picks up new procedures automatically when added to an
  existing proto file; new FILES must be registered there.
- Dev DB: only the `admin` account exists; its UUID changes on reseed. Wire ids are
  derived, so old literal ids in docs/tests are dead — take wire ids from responses.
- OrbStack docker daemon dies intermittently; recover with `orbctl start`, poll
