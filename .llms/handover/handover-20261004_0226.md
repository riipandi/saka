## Open notes carried forward

### 1. Per-bucket write permissions (plan out-of-scope, owner-settled)

Any signed-in account may upload into any bucket. The guard cannot express "uploader may write
bucket X" — the check lives at the tus creation, and the day it ships, the bucket row needs its
reader: a `public` column (or an ACL table) added **in the same change as** the authenticated
read path that consumes it, per the dead-schema rule. The private-bucket serving half (`/storage`
refusing unauthenticated reads of non-public buckets) is the other half of that change.

### 2. The SPA has no upload surface

The plan's frontend line (tus-js-client for avatar upload) was deferred: `packages/frontend`
is an empty scaffold, so there was no avatar path to switch. The probe page
(`/debug/file-upload`, debug build, `tus-js-client` UMD from the CDN) carries the client
integration until a real screen exists. `vite.config.ts` has no `server.proxy` block — the
dev-server proxy AGENTS.md describes is still aspirational; the frontend work should add it
(`/api`, `/rpc`, `/.well-known`, `/storage` → `:3080`).

### 3. Supabase schema deltas adopted for later surfaces

From the compiled-schema reconciliation (plan decision 16): `path_tokens` + folder aggregation
wait for a folder-browsing surface; `last_accessed_at` waits for read accounting;
`s3_multipart_uploads`/`_parts` were rejected outright (saka stages whole files locally). Do
not re-derive these — the plan holds the reasoning, and the compiled schema holds the shapes.

### 4. Registry runner list pins the sweep

`TestRunnersAreTheLongRunningComponentsInStartOrder` pins `queue, scheduler, upload sweep`, and
`compose_test.go` pins the area count (8, `storage` included). An area or runner added later
touches those tests in the same change.

### 5. `TusAppend`'s marker refusal is load-bearing

The append refuses a row the `tus_upload_length` marker no longer names — Stage-path files and
completed sessions — which is what keeps the completion's enqueue from firing twice. A change
to the marker's lifecycle (name, strip timing, expiry predicate) must keep both properties:
the sweep skips marker rows, and a completed session refuses appends.
