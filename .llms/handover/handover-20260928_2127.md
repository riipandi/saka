## What a fresh agent should know per area

### Cache (commit `32c4afb`)

- `cache.Cache` gained `DelPrefix(ctx, prefix)` (memory: shard-index walk; valkey: SCAN+DEL) and the generic helper `cache.Fetch[T]` in `internal/cache/readthrough.go` — jsonv2 serialization, pure-bypass semantics: `bypass=true` reads the source and neither reads nor writes the cache.
- Consumers: `modules/appconfig` `Settings` (keys `settings:public`, `settings:gate:<key>`; sealed items never cached; Update/Reset invalidate after commit) and `modules/identity/authorization` `Service` (fingerprinted list keys `sha256[:8]`, `GetRole` by id; every role write does `DelPrefix("authz:")`; user-grant writes do not).
- `nocache` is a `bool` body field on four ConnectRPC requests only (`ListPublic`, `ListPermissions`, `ListRoles`, `GetRole`). The REST `?nocache=1` convention is documented but has no consumer today — no cached endpoint reads the DB via REST.
- JWKS was already cached (`jwtutils.NewCachedKeyProvider`); `GET /api/configuration` is in-memory. Neither was touched.
- Details live in `internal/cache/README.md` (the `DelPrefix` / `Fetch` sections name the consumers).

### Settings seeder (commit `565f401`)

- `database/seeders/settings_factory.go`: one row per non-sealed catalog item at its declared default, `ON CONFLICT (key) DO NOTHING RETURNING key` (QueryRow scan → `datastore.ErrNoRows` = skipped). Sealed items are skipped — the seeder holds no cipher.
- Registered in both `seeders.System()` and `seeders.All()`; `cmd/initialize.go` picks it up automatically.
- Known trade-off, deliberate: a code-level default change later will read as an "override" in old seeded rows (the seeder never overwrites). The doc comment says so.

- Classification tables in `internal/guard/ratelimit.go`; a new public procedure must be classified or `internal/guard/ratelimit_test.go` fails. Guard tests import `authnv1connect`/`identityv1connect`.
