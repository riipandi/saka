## 2. Read this before touching the config layer

The configuration design is the least obvious thing in this repository and the easiest to break by
"fixing" it. It was rebuilt twice this session, so the current shape is deliberate.

### The config file is the single source of truth (internally: "Option B")

Precedence, lowest to highest:

1. built-in defaults (`config.Default()`)
2. the JSON config file (`--config-file`, `CONFIG_FILE`, or `app.config.json`)
3. command-line flags (only `serve` has any: `--host`, `--port`, `--base-url`)

**The environment is deliberately NOT a layer.** It is a value table the config file *references*:

- `"url": "env:DATABASE_URL"` — the whole value comes from the variable
- `"url": "postgresql://u:p@${DB_HOST}:5432/tango"` — inline interpolation

Consequences that must be preserved:

- A variable nobody referenced cannot change a value. A stray `export` in a shell is inert.
- Users name variables whatever they like; the file decides which key each one fills.
- **The file is required.** A missing one is `ErrNoConfigFile`, not a fallback to defaults.
  `config:generate` is therefore the first command a fresh checkout runs.
- **Do not use `config.LoadDefaultConfig` from the AWS SDK** (or any other library that reads
  `AWS_*`/`*_URL` variables on its own). It would reintroduce an environment layer by the back door.

### Resolution is deferred at the CLI

`initConfig` (in `cmd/config.go`, wired as the root `Before`) stores a `configState{cfg, err}` on the
context and **never fails**. The command that actually needs the configuration is the one that
reports the error. This is what lets `config:generate` (writes the file) and `key:generate` (runs
before the variables it references exist) work at all.

Two accessors:

- `configFrom(ctx)` — resolves, does not validate. Used by `migrate:*`, `db:*`, `health`,
  `config:print`.
- `fullConfigFrom(ctx)` — resolves **and** validates. Used by `serve` only.

**Never move resolution back into a hard failure in `Before`.** It breaks `config:generate` and
`key:generate`.

### An unresolved directive drops the key, it does not fail the load

If `env:FOO` names a variable that is not set, `configFileLayer` **removes the key from the layer**
so it keeps its default, and records `key → variable name` in `Config.unresolved`.

Why: `migrate:status` reads only `database.url` and must not be blocked by an unset
`AUTH_PRIVATE_KEY`. `Validate` reports an unresolved variable **only where it leaves the key
unusable**, via `Config.unsetNote(key, resolved)` — so `app.mode` falls back to `development`
silently, while `database.url` gets "the DATABASE_URL variable is not set".

### One file per stage of a Config's life

| File | Holds |
|---|---|
| `types.go` | the shape: `Config` + sections + driver/format constants |
| `defaults.go` | `Default()`, `DefaultsMap()`, `DefaultDataDir`, `DefaultS3Region`, mode/log consts |
| `duration.go` | `durationKeys`, `normalizeDurations`, `asSeconds` |
| `keys.go` | `Keys()`, `Values()`, `filterKnown`, reflection flatten |
| `env.go` | `Delim`, `Layer*`, `EnvName`, `interpolateEnv`, `lookup` |
| `file.go` | `configFileLayer`, `interpolate`, `expandInline`, `ErrNoConfigFile`, `ErrUnresolvedVar` |
| `flags.go` | `flagBindings`, `FromCommand`, `Resolve`, `readEnvFile` |
| `validate.go` | everything done to a *resolved* Config: `Validate`, `Redacted`, `Masked`, `RedactDSN`, `RedactKVURL`, `String` |
| `sample.go` | `Sample()`, `secretKeys`, `envKeys`, `nullKeys`, `nest`, `renderable` |
| `config.go` | package doc, `Options`, `Load`, `merge`, `Origin` |

Do not add a file for a single function. A constant belongs beside the defaults that reference it.

### Durations are read as seconds, per key

A duration key holds a plain number in the file: `"cache": {"ttl": 300}`, never `"5m0s"`.

This **cannot** be done with a mapstructure decode hook. `time.Duration` is an `int64`, so a hook
cannot tell it from an ordinary integer, and koanf hands a JSON number over as a `float64` whose
value lands in the *nanoseconds* field — `900` became `900ns` in a probe. Hence the explicit
`durationKeys` list. A test (`TestDurationKeysMatchTheStruct`) asserts the list equals the set of
`time.Duration` fields on `Config`, so a new duration field fails until it is listed.

`storage.s3.signed_url_expires` is the newest member of that list.

### The three key lists in `sample.go`

| List | Meaning |
|---|---|
| `secretKeys` | never written literally; `Redacted`/`Masked` hide it. Written as `env:EnvName(key)` unless `envKeys` overrides. |
| `envKeys` | written as a directive naming an **explicit** variable. Needed when the name differs from `EnvName(key)`, or when a non-secret value should be a directive rather than a literal. |
| `nullKeys` | written as `null` rather than `""`. |

A key may be in both `secretKeys` and `envKeys` — that is how a secret gets a pinned variable name.
The overlap is currently **exactly one key, `kvstore.url`** (it is `VALKEY_URL`, not
`KVSTORE_URL`), and a test asserts that.

`EnvName("storage.s3.access_key_id")` already yields `STORAGE_S3_ACCESS_KEY_ID`, so the S3
credentials are in `secretKeys` only. Adding them to `envKeys` too would restate a rule, not pin a
name.

### Two secret renderings, kept apart on purpose

- `Redacted()` → `[redacted]`. The fail-safe behind `Config.String()` and anything log-shaped.
- `Masked()` → `head****tail` (4 + `****` + 4; anything under 16 chars is fully redacted).
  Used **only** by `config:print`.

A log is read by everyone with log access, so a partial secret there leaks slowly. A report is read
by the operator, who could read the value anyway. Keep them apart.

A connection string is never masked: `RedactDSN` and `RedactKVURL` reduce it to `host:port/database`.
`RedactKVURL` exists separately because `pgx.ParseConfig` **rejects** `redis://` URLs — using
`RedactDSN` would replace the whole target with `[redacted]` and lose the host.

## 4. Load-bearing decisions — do not relitigate without cause

- **Optional backends are opt-in, never required.** Postgres + local storage must be enough for the
  default local path. No Valkey, S3, or SMTP required.
- **Driver vocabulary**: cache `memory|kvstore`, rate_limit & session `database|kvstore`, log
  `pretty|structured`, storage `local|s3`. A key-value backend is named by role, not by product.
- **`Enable` gates availability; the per-feature `driver` field chooses the backend.** Switching
  `kvstore.enable` on moves nothing by itself. A driver pointing at a switched-off backend is a
  validation error naming every offending driver.
- **`storage.s3` is validated only when `storage.driver` is `s3`.** A local deployment may keep
  credentials in the file for a later switch.
- **`storage.s3.region` has a concrete default (`us-east-1`).** The S3 client refuses to resolve an
  endpoint without a region — *even against MinIO, which ignores the region* — and every request
  fails. An unset `STORAGE_S3_REGION` must leave a usable value; an explicitly empty region is
  still an error.
- **`storage.s3.force_path_style` defaults to `true`.** MinIO and Silo need it, and the SDK does not
  fall back on its own (`bucket.localhost` does not resolve — verified by probe).
- **`storage.s3.signed_url_expires` is held inside `1s..7d`.** The protocol caps a signed link at
  seven days, and the client reads `0` as "use my own 15-minute default" rather than as a lifetime.
- **`db:export` writes plain first, compresses after.** Never read a compressor's buffer before
  closing it.
- **`db:import` takes the file as a required positional argument**, always confirms, ignores the DDL
  in the file, and reads all COPY blocks into memory before ordering them by foreign key.
- **Confirmation prompts gate on a real TTY** (`golang.org/x/term`, because `/dev/null` is also a
  character device) and proceed when piped, so CI never blocks.
- **No `//nolint`** — fix lint findings at the source.
- **No `git checkout <file>` / `git restore` on uncommitted work.** (See §7.)
- **Tool configs live in `.config/`, except `.oxfmtrc.json` and `.oxlintrc.json`, which must stay at
  the repository root** — both resolve `ignorePatterns` relative to their own directory, so moving
  them silently disables every root-anchored pattern.
- **Never add, remove, or rename a top-level package or directory** without an explicit request.
  Extend an existing package.

## 7. Traps that cost time this session

**`git checkout <file>` destroyed uncommitted work.** A temporary patch was reverted with
`git checkout internal/config/validate.go`, which restored the file to HEAD and wiped every
uncommitted S3 change in it. It was recovered by re-applying four edits as an asserted Python patch
(each `assert s.count(old) == 1`, so it cannot apply partially) and re-verified. To sanity-check
"would this test fail if the feature were removed", copy the file to memory or `/tmp` first — never
reach for git.

**`time.Duration` cannot round-trip through a JSON number.** See §2. `900` becomes `900ns`.

**`encoding/json/v2` does not sort map keys.** Deterministic output needs `json.Deterministic(true)`.
It also has no `MarshalIndent` (use `jsontext.WithIndent`) and refuses `time.Duration` outright.

**`pgx.ParseConfig` rejects `redis://`.** Hence `RedactKVURL`.

**A `null` in the config file means "use the default"**, not "empty the value" — verified against
koanf. This is what makes `path_prefix: null` round-trip correctly.

**`golangci-lint`'s `unused` flags a method reachable only from a debug-tagged file.** Debug-only
command actions live in `cmd/migrate_debug.go` for exactly this reason.

**A test stub `Reader` does not echo**, so a confirmed prompt and a result row can appear glued
together. That is a test artifact, not a bug.
