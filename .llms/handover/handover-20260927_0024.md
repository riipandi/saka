## Key gotchas learned this session (also in memory)

- **Order sensitivity, twice**: a static `/me` pattern must be declared BEFORE a
  `/{id}` pattern in BOTH the chi router (`modules/identity/user/handler.go`) AND
  the guard `RestRules` table (`internal/guard/rules.go`). Either order reversed
  makes the param pattern swallow `me` → spurious 404 (guard compares the literal
  word "me" against the caller subject).
- **audit.Record inside a transaction**: the recorder never returns errors, but a
  SQL error in the audit INSERT (e.g. `user_id` FK violation for an unknown
  account) ABORTS the surrounding tx → pgx fails at commit with "commit
  unexpectedly resulted in rollback". Any service recording an event with a
  `user_id` must verify the account exists before opening the transaction.
- **api/specs mirror lag**: the mirror is written by the running Yaak desktop
  app, not the CLI. CLI mutations (`yaak request create/update/delete --json`)
  hit the workspace immediately (verify via `yaak request show`); mirror files
  can lag indefinitely. Workspace state is the truth; never hand-edit the mirror.
- **Yaak CLI**: positional workspace id `wk_kBiMYTkhPP`; `--json` payload for
  create/update; `--yes` for delete; `yaak request schema http` for the model.
- SignIn RPC field is `identity`, not `username`.
