Added `log.level` → `LOG_LEVEL`.
3. **Sample opens with `"$schema": "config.schema.json"`** (relative; const `config.SchemaFileName` in `file.go`). Loader ignores the key (proven: `config:validate` passes with it present).
4. **`config.schema.json` is GENERATED** — user decision recorded in memory. `internal/config/schema.go` builds it from the `Config` struct via `invopop/jsonschema` (dep added, v0.14.0) + post-processing:
   - `DoNotReference` → one inline tree; only `$defs.envDirective`.
   - Descriptions come from Go doc comments (`AddGoComments("github.com/riipandi/tango/internal/config", ".")`).
   - Defaults injected from `DefaultsMap()`; `time.Duration` converted to seconds; empty-string defaults omitted.
   - `stripRequired` (reflector marks everything required; the file must be allowed to omit keys).
   - `wrapScalars`: every scalar → `anyOf [literal, #/$defs/envDirective]`; description/default move to the union level, literal branch keeps enum.
   - `unionWithDirective` additionally wraps all `listKeys` (arrays) and `mapKeys` (`otel.headers`) — this fixed the editor warnings "expected array got env:LOG_TRANSPORT" / "expected object got env:OTEL_HEADERS".
   - Declares a `"$schema"` string property so the generated file's own `$schema` key validates.
   - **Draft is `http://json-schema.org/draft-07/schema#`** — user's linter rejected draft 2020-12 ("meta-schema features ($dynamicRef) not yet supported"). Note `$defs` under draft-07 still works via plain JSON-pointer `$ref`.
5. `config:generate` now always writes `config.schema.json` beside the output (same `--overwrite` guard across all three files); output lines report each written file. The schema file is **gitignored** (`.gitignore` already had the entry); the old `public/config.schema.json` and `web/output/config.schema.json` are deleted from disk, `public/` is empty of it, and `.oxfmtrc.json` lost the `!/public/config.schema.json` exception.
