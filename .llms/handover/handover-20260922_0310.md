## 3. Load-bearing decisions — do not relitigate without cause

These were each chosen against an alternative, usually with the user. Reversing one needs a reason,
not a preference.

- **One collector address for three signals.** `otel.endpoint` is the only place a collector is
  named. A signal that needs a different route sets a path. A second address would be a second
  configuration source deciding where telemetry goes.
- **`otel.protocol` is shared, not per-signal.** A collector accepts one protocol per listener, so a
  deployment that needs two is running two collectors. Values: `grpc`, `http/protobuf` (default),
  `http/json`.
- **`grpc` reuses `otel.endpoint`.** The exporter is addressed by host and port, so
  `Config.CollectorEndpoint()` reduces a URL to `host:port` and `Config.CollectorSecure()` reads TLS
  from its scheme. Keeping the scheme is what lets one address serve both protocols.
- **`http/json` is refused for metrics and logs.** Only `otlptracehttp` encodes JSON in the Go SDK;
  `otlpmetrichttp` and `otlploghttp` have no JSON encoder at all. Shipping protobuf to a collector
  expecting JSON fails far from the key that caused it, so `Validate` refuses it by name.
- **`otel.headers` is one shared map, and every value is a secret.** An authorization token is why
  the key exists, and the names inside are chosen by the user, so there is no per-entry key to list.
  `redactHeaders` keeps the names and hides the values.
- **`otel.queue.max_size` bounds every signal's buffer.** It is the setting that keeps export off the
  request path: recording enqueues and returns, a full queue drops the oldest item.
- **The environment is not a source.** Every exporter option and every resource attribute is passed
  explicitly, so the SDK cannot read `OTEL_EXPORTER_OTLP_*`, `OTEL_SERVICE_NAME`,
  `OTEL_RESOURCE_ATTRIBUTES`, or `OTEL_SDK_DISABLED`. The gRPC exporters read those variables too
  (`ApplyGRPCEnvConfigs` runs before a caller's options), which is why TLS material is closed with
  **explicit credentials** rather than `WithInsecure` — credentials take priority over both the
  insecure and the TLS default.
- **`Slog()` is the one frontend.** `Log()` exposes the LogLayer core for what slog cannot express,
  not as a second way to write a line. Using both would split the codebase into two idioms, the
  second skipping the handler everything else is wired through.
- **`log.format` selects only the console renderer.** A file or a collector keeps JSON regardless, so
  asking for a colourised console cannot put escape codes in the file.
- **A route is applied only when the configuration names one or the endpoint carries none.** An
  address that already names a route says where the signal goes.
- **Signals are opt-in.** No redundant `otel.enable` master switch — two flags that can disagree.
- **The Victoria healthchecks are gone on purpose.** VictoriaLogs v1.52+ and VictoriaTraces v0.11+
  ship distroless images with no shell and no HTTP client, so an in-container probe cannot work
  (`exec: "nc": executable file not found`). The real probe is `task metrics:health` from the host.
  Restore the healthchecks only when `-health` ships (VictoriaLogs#1741).
- **Perses resources are `GlobalDatasource`, not project-scoped `Datasource`.** A project-scoped file
  is provisioned into nothing and logs `project "default" doesn't exist`.
- **CGO_ENABLED=0 in the Vite build plugin.** See §7 — it is what makes the static release link work.

## 4. How to prove it works

### Unit and package tests

```sh
task check && task lint
CGO_ENABLED=0 go test ./... -count=1          # 16 packages
CGO_ENABLED=0 go test -tags debug ./... -count=1
go test -race ./internal/observer/ ./internal/logger/ ./internal/config/ ./cmd/
```

`internal/logger` and `internal/observer` each have a `grpc_test.go` that starts a **real gRPC
listener** (`go.opentelemetry.io/proto/otlp` + `google.golang.org/grpc`) and asserts a span or record
arrives with the configured headers. The HTTP paths use an `httptest` collector. Both are proven
without Docker.

### End to end against the stack

```sh
task metrics:up                # collector + 3 Victoria services + Perses
task metrics:health            # all four endpoints must answer

# logs
LOG_TRANSPORT=console,otlp OTEL_SERVICE_NAME=saka-check task metrics:smoke
task metrics:query -- 'service.name:"saka-check"'

# traces + metrics, HTTP
OTEL_TRACING_ENABLE=true OTEL_METRICS_ENABLE=true task metrics:smoke:otel
task metrics:traces

# traces + metrics, gRPC (needs the collector's 4317 listener, which is published)
OTEL_PROTOCOL=grpc OTEL_ENDPOINT=localhost:4317 \
OTEL_TRACING_ENABLE=true OTEL_METRICS_ENABLE=true task metrics:smoke:otel
```

The metric push is on a **60s interval** by default, so a query immediately after a run can come
back empty. `curl --get --data-urlencode 'match[]=saka_otel_smoke_total'
http://localhost:8428/api/v1/series` shows the series once it has landed.

## 6. The audit: known weaknesses in what this session built

An end-of-session review found no cut corners — the foundations are honest and tested — but eight
pieces of **residue**. They are listed worst first. None is a correctness bug in the default
configuration; all are real.

**1. Log↔trace correlation is dead in practice.** This is the most significant one. The `otellog`
transport extracts the trace context from `params.Ctx`, and it works — proven with a throwaway probe:

```text
body="without context"  trace_id=""                    span_id=""
body="with context"     trace_id="z6\xd6<%..."         span_id="\xb5\x06\x16)..."
```

So `InfoContext(ctx, ...)` carries the trace ID and `Info(...)` does not. **No call site in the
repository uses a context** — every one is `Info(...)`, including `cmd/logger.go:142`. The capability
exists, nothing uses it, there is no helper, no test, and no guidance in `AGENTS.md`. The main reason
to have logging and tracing in one stack does not work.

**2. Four functions are duplicated across the two packages.**

| Function | Copies |
|---|---|
| `grpcTransport` | `internal/logger/otlp.go:194`, `internal/observer/metrics.go:46` — identical |
| `tlsConfig` | `internal/logger/otlp.go:208`, `internal/observer/metrics.go:60` — identical |
| `grpcCompressor` / `logCompressor` | same logic, two names |
| `logPath` / `signalPath` | same logic, two places |

This repository's whole thesis is one source of truth per decision; these are four exceptions.

**3. `log.otlp.timeout` cannot be configured.** `otlpTimeout = 10 * time.Second` is hardcoded in
`internal/logger/otlp.go`, while traces have `otel.tracing.export_timeout` and metrics have
`otel.metrics.export_timeout`.

**4. One comment is now wrong.** `observerShutdownTimeout` (10s) says "the metric reader's own
timeout is a fraction of it". `DefaultOTELExportTimeout` is also 10s — equal, not a fraction. Worse,
reading `PeriodicReader.Shutdown` shows it **prioritises the caller's context** when one has a
deadline, so the reader's own timeout is not used at all. The comment explains behaviour that does
not occur.

**5. The per-signal paths are silently ignored under gRPC.** `otel.tracing.path`, `otel.metrics.path`,
and `log.otlp.path` are validated as paths, but the gRPC branch never reads them. Setting a path with
`protocol: grpc` has no effect and says nothing.

**6. Exporter errors bypass the pipeline.** The SDK's default error handler writes to **stderr via
`log.Print`** (verified in the module source). `otel.SetErrorHandler` is never called. A dead
collector therefore never reaches the configured transports — in a project whose stated thesis is one
pipeline.

**7. Speculative API with no callers.** `ResourceAttributes` has zero non-test callers and is
exported only so a test can assert on it (a smell in itself). `Log()` has zero callers. `SetGlobals`
has one caller, but **nothing reads the globals it sets today** — `otel.Tracer()`,
`otel.GetTracerProvider()`, and `otel.GetMeterProvider()` appear nowhere outside tests. Be precise
about this one: `SetGlobals` is not wrong, it is *early*. It is exactly what makes an
`otelhttp`-style middleware or any library that instruments through the global API report into this
pipeline, and `internal/transport` is where that middleware will live. So the decision is not "delete
`SetGlobals`" but "keep it until the transport exists, and delete it only if that layer turns out to
pass providers explicitly instead". `ResourceAttributes` and `Log()` have no such future — they have
no consumer by design, so they are the ones to remove unless the user names a use.

**8. `MetricsHandler` unreachable** — see §5.

### Suggested order of repair

1. **#1 and #2 first.** Correlation is a feature, not polish; duplication is a real maintenance cost.
2. **#4, #5, #6 in one small pass** — a comment, a validation rule, and an error handler.
3. **#3 and #7 need a decision, not a patch.** Ask the user whether `Log()` and `ResourceAttributes`
   are going to be used. If not, delete them rather than keeping API nobody calls. `SetGlobals` is a
   separate case — see #7, it is waiting on `internal/transport`, not dead.

## 7. Traps that cost time this session

**`go get` on an unrelated OTel package silently raises `otel/log` past the pin.** This happened while
adding the metric exporter: `otel/log`, `sdk/log`, and `otlploghttp` jumped to v0.22.0, and
`go.loglayer.dev/transports/otellog/v3` v3.0.0 stopped compiling (`undefined: otellog.StringValue`).
It was built against `otel/log` v0.19.0; OTel moved `KeyValue` and `Value` into
`go.opentelemetry.io/otel/attribute` in v0.20.0. **After any `go get`, re-check those three versions**
and put them back with `go mod edit -require`. The trace and metric exporters are on the core version
line and stay free.

**`task build` failed with `ld: library 'crt0.o' not found`.** Cause: `internal/observer` pulls
`prometheus/client_golang`, which has a `darwin && !ios && cgo` file, so the package becomes a cgo
package. With `CGO_ENABLED=1` (the macOS default) the release link flag `-extldflags -static` cannot
resolve. `.goreleaser.yaml` already set `CGO_ENABLED=0`, so `task release` never hit it; the
Vite plugin's build path did not. Fixed once in `runGoBuild` (`plugins/plugin-golang.ts`), which both
build paths go through. The library has a pure-Go fallback, so nothing was lost.

**VictoriaLogs and VictoriaTraces are distroless now.** No shell, no `nc`/`wget`/`curl`. An
in-container healthcheck fails with `exec: "nc": executable file not found in $PATH`, Docker marks
the container unhealthy, and every `depends_on: {condition: service_healthy}` behind it never starts
(Perses was stuck in `Created`). See §3.

**VictoriaMetrics OTLP ingest is protobuf only.** It answers a JSON request with
`json encoding isn't supported for opentelemetry format. Use protobuf encoding`. The collector's
`encoding: proto` handles it.

**The Victoria routes are not the protocol's routes.** VictoriaLogs serves OTLP on
`/insert/opentelemetry/v1/logs` and VictoriaTraces on `/insert/opentelemetry/v1/traces` — **not**
`/v1/logs` and `/v1/traces`. VictoriaMetrics ingests on `/opentelemetry/v1/metrics`. The collector
rewrites them, which is why the application names no path at all.

**`go test ./database/` is flaky under testcontainers timing.** One run of
`TestRestoreWithoutTruncateFailsOnConflict` failed and three subsequent runs passed. `database/` was
not touched by this session; do not chase it as a regression.

**koanf handles a nested map correctly; the config layer did not.** Before writing `mapKeys` the
behaviour was probed in `/tmp/koanfprobe`: `confmap.Provider` with `{"otel.headers": {...}}` and a
dotted key both decode into a `map[string]string` field. The bug was `flattenNested` walking the map
into `otel.headers.authorization`, a key that is not part of `Config`, which `filterKnown` then
dropped — leaving the header silently unset. **Probe a library before designing around it.**

**`.env.example` is the user's file and stays lean.** A two-line explanatory comment added above
`OTEL_ENDPOINT` was removed by hand. Variable names and values only; the reasoning belongs in
`README.md` and `AGENTS.md`.

## 9. House rules for the next agent

Unchanged from the previous handover, repeated because they are the ones that get broken:

- Chat replies in Indonesian; code, comments, commit messages, and repository documentation in
  English.
- Never commit unprompted. Finish the work, recommend a one-line commit title
  (`{feat,fix,docs,refactor,chore}[(scope)]: <message>`) plus the changed paths, and let the user
  commit. Never push.
- Stage explicit paths only — never `git add -A`.
- Comments explain what the code cannot: an invariant, a security rule, a protocol requirement.
  Never restate the code. Never leave `phase *` / `Step N` / `TODO(plan)` markers.
- **Never `git checkout <file>` or `git restore` on uncommitted work.** The previous session lost
  work that way. To check "would this fail if the feature were removed", copy to `/tmp` first.
- Read a file before assuming its behaviour. Most of `internal/**` and all of `modules/**` are
  one-line packages.
- No `//nolint` — fix lint findings at the source.
- `AGENTS.md` is the single instruction source for all agents, and it was updated this session for
  every one of these decisions. Keep it accurate.
