## Build flag contract (one source: `vite.config.ts`)

plugin-golang targets are canonical; nothing else may build binaries:

| Target | Tags | Extra |
|---|---|---|
| debug | `debug,noasm,nounsafe` | version ldflags only (debugger-friendly) |
| release | `release,noasm,nounsafe` | `-trimpath -buildmode=pie -buildvcs=false` + version stamps + `-w -s -extldflags -static` → **64.07 MiB** (debug is 91.64 MiB) |
| goreleaser | `release` | same flags, stamps from the tag — **does NOT carry `noasm,nounsafe`**; the only remaining delta, left as the shipping channel |

Verification recipe: `go version -m build/release/saka` must show
`-tags=release,noasm,nounsafe` and `-buildmode=pie`; `ls` size must match the
plugin's logged "(64.07 MB)". If the on-disk binary disagrees with the log, a
clobbering `go build` ran after the plugin — find it.

## Known quirks / open items

- `saka -V` prints help, not the version — `internal/config.AppVersion` is
  stamped but not wired to the CLI's version display. Harmless, unfixed.
- `saka serve` has no `--port` flag; port comes from `SERVER_PORT` in the
  config/env-file, and `.env.local`'s value wins over the process environment.
- `plugins/plugin-golang.ts` release target passes `-extldflags -static` on
  darwin where the local `cc` rejects it — the plugin builds anyway (it drops
  or ignores it per-OS); a manual raw `go build` with the same flags fails on
  darwin. Do not "fix" the vite config flags to match a manual command.
