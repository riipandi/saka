## Session decisions worth keeping

- Event catalog is **curated dot names** in `modules/webhook/events.go` (76 mapped audit events
  - `webhook.test`); never rename a shipped name; unmapped audit events are never emitted. The
  audit vocabulary's own catalog lives in `internal/audit/catalog.go`; two source-level tests
  pin the lists to one set.
- All audit events are subscribable; `*` wildcard and empty list mean "everything". No proto
  enum.
- TypeID wire prefixes: `whk_`/`whd_`/`wha_`; DB columns stay UUID; `X-Webhook-Id` carries the
  wire form.
- SSRF stance: `webhook.allow_private_network` (default `false`) refuses loopback/private/
  link-local hosts per attempt; deliveries never follow redirects (signature headers must not
  travel). Residual TOCTOU (resolver answers twice in one attempt) documented, not closed.

## Audit round results (2026-09-30)

Fixed in this session: transactional `Notify()` after executor-bound enqueues (was a 60 s
fallback-poll delay, proven E2E); invisible delivery row = retryable error (closes the
claim-ahead-of-commit race); attempt insert + status write in one tx with
`WHERE status = 'pending'` (no replay overwrites); transient endpoint-read failures retry
instead of stranding a pending delivery; migration 00006 carries
`uq_webhook_delivery_attempts_number` and `idx_webhook_delivery_attempts_created_at` inline
(no ALTER — user asked; the separate 00012 file was created, used to roll a stamped DB back,
then deleted); retry classification (redirect + 4xx except 408/429 fail on first answer);
delivery retention 30 days via `webhook_prune`; `MatchEndpointIDs` selects ids only; header
values pattern-checked in proto; `testBody.webhook_id` uses the wire form.

Not acted on (noted, low value): `event_types` predicates may not use the GIN index (fine at
current scale); `Notify()` fires even when zero endpoints match (harmless extra fetch).
