## What landed

`internal/mailer` is implemented on `github.com/emersion/go-smtp` v0.25.0 +
`github.com/emersion/go-sasl` (the user chose both; `go-smtp` requires `go-sasl`, so they are
adopted as a pair). `serve` resolves `*mailer.Service` before the listener opens, so a broken
template fails the run rather than the first send.

- `mailer.go` — `*Mailer`: one session per `Send`, closed by it. Implicit TLS when
  `mailer.smtp_secure`, STARTTLS when the server advertises it, plaintext (reported as a warning)
  when it does not. PLAIN then LOGIN for auth, **refused outright on an unencrypted session that
  leaves the machine** (see "Credential guard" below). `mailer.timeout` bounds dial, handshake,
  every command, and the body; the caller's context closes the connection through
  `context.AfterFunc`.
- `envelope.go` — `envelope.prepare` + `envelope.writeTo(io.Writer)`, with a `bodySource` that is
  either the caller's two strings or a closure rendering one template. The message is **streamed
  into the session's `DATA` command**; `SendMail` is not used because it takes an `io.Reader` and a
  body produced on demand cannot be given as one. `multipart/alternative` with the text part first
  when both bodies exist, a single part otherwise; quoted-printable bodies, RFC 2047 encoded
  subject and sender name, CRLF everywhere, generated `Message-ID`. `Bcc` is an envelope recipient
  only. Address and header values carrying a line break are refused. A body failure aborts with
  `RSET` rather than closing `DATA`, so a half-written message is never accepted.
- `error.go` — `ErrNotConfigured`, `ErrNetwork`, `ErrTimeout`, `ErrCanceled`, `ErrAuth`,
  `ErrInsecureAuth`, `ErrRejected` (5xx), `ErrTemporary` (4xx), all `errors.Is`-matchable. The
  server's own reply text is never repeated in `Error()`.
- `templates.go` — `*Templates` parses the embedded `web/email/*.tmpl` as HTML/text pairs at
  construction; `RenderTo(w, name, kind, view)` streams one rendering, `Render` returns both as
  strings; both produce identical bytes (pinned by a test). Unknown name refused.
- `data.go` — one struct per template. The struct field names must match the `{{.Data.…}}` names the
  Vite build writes.
- `service.go` — `*Service` pairs the mailer and the templates; `Send` renders then submits, on the
  streaming path.
- `cmd/mailersmoke.go` — `mailer:smoke`, plus `task mailer:smoke -- --to=…`.
- `internal/config` — `mailer.timeout` (default 15s) and `mailer.smtp_allow_plaintext_auth`
  (default false, `MAILER_SMTP_ALLOW_PLAINTEXT_AUTH`), the former in `durationKeys`.
- `internal/registry` — `*mailer.Service` provided.
- `email/templates/api-key-expiring-soon.tsx` — `{{.Data.ApiKeyName}}` → `{{.Data.APIKeyName}}`
  so the Go struct field keeps its initialism (staticcheck ST1003).

## Credential guard (the fix this session)

`go-sasl` sends the password as soon as the server asks, with no opinion about the transport.
`net/smtp` refuses that case inside `PlainAuth`; `go-sasl` has no equivalent, so
`Mailer.authenticate` refuses it itself, before any mechanism is chosen. `ErrInsecureAuth` is
returned and is **exported**, because a caller acts on it (set TLS, enable STARTTLS, or opt in) and
must not retry it as a rejected credential.

Three things make a session safe, in `credentialIsSafe`:

1. `client.TLSConnectionState()` reports encrypted — the **session's** answer, not the configured
   intent, so a `smtp_secure` run that failed to negotiate never reaches the check;
2. `isLoopbackHost(settings.SMTPHost)` — `localhost`, or an IP literal for which
   `net.IP.IsLoopback()` is true, so a local Mailpit needs no certificate;
3. `mailer.smtp_allow_plaintext_auth`.

It is deliberately **not** a `Validate` rule: whether a server offers STARTTLS is only known once it
has been asked, and a config check would reject the ordinary submission server
(`smtp.gmail.com:587` + credentials + STARTTLS). That reasoning is pinned by
`TestValidationAcceptsRemoteCredentialsWithoutTLS` and `TestRemoteHostWithCredentialsIsAValidConfiguration`.

The classification keeps the reason: `classify` sets `Kind = ErrAuth` and `Error.cause =
ErrInsecureAuth`, so `errors.Is(err, ErrAuth)` and `errors.Is(err, ErrInsecureAuth)` both answer.

## Streaming path (the other fix this session)

`RenderTo` writes one rendering into a writer; `bodySource` lets the envelope ask for a rendering
directly into the SMTP `DATA` writer. Measured on an M2 Pro (`internal/mailer/bench_test.go`):

| Operation | Time | Allocs |
| --- | --- | --- |
| `RenderTo` one rendering (send path) | ~4.6 µs | 58, 1.5 KB |
| `Render` both renderings | ~10.6 µs | 73, 20 KB |
| Parse every template (once per process) | ~182 µs | 2318, 276 KB |

A submission costs 60–100 ms against a real server, so rendering is under 0.01% of it. The parsed
templates **are** the cache; no second layer is worth having. Memoizing by template data would
retain reset tokens past their use, and `internal/cache` would add a network round trip for content
already in the binary.

## Decisions worth not relitigating

- **The library exports no sentinel for "this server has no STARTTLS".** `NewClientStartTLS`
  returns a plain error whose text is `smtp: server doesn't support STARTTLS`, so
  `startTLSUnsupported` matches the text and `TestStartTLSUnsupportedMatchesTheLibraryMessage` pins
  it against a real Mailpit container. A failed STARTTLS attempt closes its own connection, so the
  plaintext fallback dials again — only a TLS-less server pays for the second dial.
- **A STARTTLS session cannot be greeted explicitly.** The handshake sends its own greeting before
  the client is handed back, so it introduces itself with the client's default name; only the
  plaintext path calls `Hello(sender domain)`. Accepted, not worked around.
- **`net/smtp` was weighed and left out.** It is frozen, has no timeout of any kind (`Dial` uses
  `net.Dial` with no deadline; no `context.Context` anywhere), no implicit-TLS helper, and no typed
  error — so the deadline wrapper and the error classification would have to be written on top,
  which is most of what `go-smtp` provides. Its one advantage is the `PlainAuth` guard, which is now
  implemented here. Recorded in the library decision records.
- **`LoginNewDeviceData.DateTime` is the one `time.Time`**, because that template formats it
  itself. Every other date is a string, because these values travel the queue as JSON.
- **The sender logo is `app.base_url` (fallback `app.assets_url`) + `/images/logoEmail.svg`.**
  `app.assets_url` defaults to `/static`, which **this transport does not mount** — the SPA is
  served at the root by `web.SetupStatic`. Using `assets_url` first produced a 404 link, so the
  public origin wins. If `/static` is ever mounted, revisit.
- **No connection pool.** An SMTP session is stateful; a pooled one would have to be verified before
  reuse. One session per send.
- **`--env-file` outranks the shell environment** in this repo's config resolution, so
  `MAILER_SMTP_SECURE=true task mailer:smoke` has no effect while `.env.local` sets it. Use a
  `--config-file` override or edit the env file when testing a TLS flip.

## Left alone

- `key:rotate` still prints `not yet implemented`. ConnectRPC routes and the auth middleware are
  still not mounted.
- The plaintext warning is emitted per session, so a deployment without TLS logs it on every send.
- **No queue integration yet, deliberately.** `internal/jobs` has no email job, and the integration
  belongs at the module call site, not inside `internal/mailer`: a job must be enqueued with the
  caller's transaction (`TaskAddOp.Executor(tx)`) so a mail is not sent for a rolled-back change,
  the job payload should carry the template data rather than a rendered body, and `ErrRejected`
  should reach the dead letter rather than burn every retry (the queue has no "permanent failure"
  concept yet — decide that when the job exists). `Send` stays synchronous so `mailer:smoke` can
  prove the SMTP path without the queue.
- `modules/**` are still scaffolds, so nothing calls `mailer.Service` yet. The first feature that
  sends mail should take it from the injector, not build one.
