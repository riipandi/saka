## Session-specific traps (not already in AGENTS.md / architecture.md)

- **Perses provisioning creates, never overwrites**: to apply a changed
  dashboard file, `DELETE /api/v1/projects/tango/dashboards/<name>` (204) then
  restart the perses container. The whole `docker/perses/` dir is mounted at
  `/etc/perses/provisioning`; file names are free-form.
- **Perses `ListVariable` without `defaultValue` interpolates empty**
  (`instance=~""` → zero series → "dashboard shows no data"). Every
  instance/datname variable carries `defaultValue` + `customAllValue: ".*"` —
  keep that pattern for new dashboards.
- **Temp smoke config durations must be strings**: `"cleanup_interval": "5s"`.
  A bare `5` parses as 5 **nanoseconds** and turns the recurring-job loop into
  a hot loop (observed: 3,240 tasks in minutes).
- **Docker Desktop `host-gateway` can resolve to a bogus IP** (seen:
  `0.250.250.254`, VPN-related). Symptom: VM's `tango` scrape target fails from
  containers while the app is healthy. Fix is a Docker Desktop restart, not a
  code change; verify with `/api/v1/targets`.
- **Live smoke recipe that worked**: copy `app.config.json` to a temp dir with
  `queue.cleanup_interval: "5s"`, run
  `build/debug/tango --env-file=<tmp env with OTEL_METRICS_ENABLE=true …> serve`
  from that dir, hit `/.well-known/jwks.json` (rate-limit counter), drop a file
  into `<local_path>/staging/` (watcher → upload task → sync → storage
  counters), scrape `/metrics` for the `tango_*` series. Scheduler cron ticks
  and fetcher calls have no live driver in the default app (no cron jobs
  registered, no outbound callers) — they are pinned by unit tests
  (`sdkmetric` ManualReader; note `Int64Counter` → `Sum[int64]` and
  `Int64Histogram` → `Histogram[int64]` in `metricdata`).
