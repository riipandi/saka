### Shape in one paragraph

Pocket ID's SCIM is **outbound provisioning**: tango is the SCIM client, not the server.
One `scim_service_providers` row per OIDC client (migration 00004 already had the table —
no new migration) names a remote base URL and a bearer token sealed `enc:` at rest, shown
once in the Create answer. `tango.federation.v1.ScimProviderService` exposes five admin
procedures: `GetByClient`, `Create`, `Update`, `Delete`, `Sync`. The sync engine pushes the
client's visible accounts then groups until the remote matches the local snapshot (users
before groups so member remote-ids exist; `lastModified` fencing; 429 retry with
`Retry-After`; remote orphans deleted; a member the remote refuses skips its group).
Triggers: manual Sync + hourly recurring `scim_sync` queue (always seeded) + five-minute
debounced `scim_sync_debounced` queue via `ScimSyncNotifier`. The visibility roll is the
client's own — unrestricted means everyone, restricted means its allowed groups' members —
so provisioning cannot admit an account the sign-in would refuse.
