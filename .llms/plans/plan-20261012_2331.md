# The webapp UI revamp: skeletons, side sheets, structural polish

## Objective

Close the UI-refinement rows of `.llms/ui-components-index.md` for `packages/webapp`:
adopt the uilibs `Skeleton` (0 sites today) and `Sheet` (0 sites today) where the
index recommends them, and even out the structural polish — empty-state CTAs, list
error states, page headers — across every `(app)` page. Flow reference:
`.llms/ui-components-index.md` (read 2026-10-12) and `.llms/stylex-authoring.md`
(read 2026-10-12). Style authority: the skills `emil-design-eng` and
`apple-design`; uilibs component designs are consumed, never reshaped
(`AGENTS.md` frontend rule).

## Decisions

- **D1 (2026-10-12):** Skeleton scope is lists, detail views, and settings cards —
  proposal 2 of the owner questionnaire — not route-level Suspense fallbacks. The
  router's own code splitting already covers route boundaries; a second loading
  layer at the segment level would show two skeletons for one wait. Rejected:
  proposal 1 (lists only — detail views flash too), proposal 3 (route-level
  fallbacks — double-loading-layer cost).
- **D2 (2026-10-12):** The four long-form Dialogs migrate to `Sheet` (`side='right'`)
  — the desktop form-drawer convention; `Drawer` stays the read-only inspector
  surface it already is. Dialog remains for confirmations, secrets, and short
  inputs. Rejected: Drawer everywhere (a bottom sheet fights a 12-field form on
  desktop), migrating only the two largest (the remaining two would still be forms
  in a modal).
- **D3 (2026-10-12):** The polish pass covers empty-state CTAs, uniform list error
  states with Retry, and one shared page-header block. Charts/telemetry widgets are
  explicitly deferred — a new feature, not a refinement of existing pages.
- **D4 (2026-10-12):** The loading, empty, error, and header patterns land as four
  small shared components under `packages/webapp/src/components/` (`-skeleton-*`,
  `-empty-action`, `-list-error`, `-page-header`), composed by the views. uilibs is
  not extended: the components arrange uilibs primitives for webapp page shapes, so
  they live beside their consumers. Rejected: adding them to uilibs (they encode
  webapp page conventions, not reusable library design).
- **D5 (2026-10-12):** Existing browser tests that drive the migrated Dialogs are
  rewritten against the Sheet in the same phase — no test window where the UI is
  one shape and the suite another. No backward-compat shims for the old dialog
  components; they are deleted in phase 2.

## Execution rules

- Atomic commit per phase is authorized; each phase's heading names its suggested

- No migrations, no dev-DB reset, no Yaak updates — no backend contract moves.

## Phases

### Phase 1 — `feat(webapp): the skeleton loading layer replaces the bare spinner`

Build the three skeleton composites (`-skeleton-rows`, `-skeleton-cards`,
`-skeleton-form`) from the uilibs `Skeleton`, then replace the 20 list-level
`isPending ? <Spinner />` branches and the detail-view pending panes (roles
`-roles-view.tsx:664`, groups `-groups-view.tsx:543`, users detail, webhook detail,
oidc-client detail) with the shape-matched composite. Spinner keeps its duty on
buttons and inline actions. Validation: `vp check`, webapp suite, visual pass
against the Storybook stories.

### Phase 2 — `feat(webapp): the long forms ride the side sheet`

Re-mount the four form Dialogs as right-side Sheets (D2), delete the Dialog
wrappers the forms outgrew, update their views' open/close wiring, and rewrite the
driven browser tests (`admin-oauth-providers`, `admin-notifications`,
`admin-webhooks`, `api-keys`) against the Sheet. Validation: `vp check`, webapp
suite, the four rewritten suites, live probe of one create flow.

### Phase 3 — `feat(webapp): the empty states ask, the errors answer, the headers hold`

Empty states with create CTAs, `-list-error.tsx` with Retry on every list, and
`-page-header.tsx` adopted across admin + account views. Validation: `vp check`,
webapp suite, spot E2E (`workflow/account-audit.test.ts`, `workflow/federation.test.ts`).

### Phase 4 — `docs: the UI index adoption map`

Docs sync only: `.llms/ui-components-index.md` adoption counts and refinement
rows updated to the landed state; `.llms/architecture.md` records the
skeleton/sheet/page-header conventions; `.llms/index.md` plan row; handover
document. Full closing validation per the test matrix. The plan frontmatter and
this body move to `done` in the same commit.
