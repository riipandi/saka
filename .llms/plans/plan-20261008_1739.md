# Component library extraction to `packages/components`

## Objective

Make the UI component set reusable by future packages: extract
`packages/webapp/src/components/` (plus the design tokens it cannot live
without) into a workspace package every frontend package can consume, with
atomic commits per phase. This implements the independent-packages rule the
tree already commits to — `.llms/rules.md` line 72 ("a new frontend package is
one directory with its own config, not another root clause"), line 73
(per-package tsconfig ownership), and line 74 (a vitest project exists only
when a surface has tests).

## Current state

Every claim below was verified in the tree on 2026-10-08.

- `packages/webapp/src/components/` holds 316 `.ts`/`.tsx` files in five
  subdirectories: `base/`, `charts/`, `extra/`, `icons/`, `theme/`. 90 of them
  are `*.stories.tsx`. There are no co-located `*.test.*` files.
- The only webapp-internal code the components import is design styling and
  one hook: 236 imports of `#/styles/core/tokens.stylex`, 103 of
  `#/styles/core/colors.stylex`, 11 of `#/styles/core/utils.stylex`, 8 of
  `#/styles/core/popup.stylex`, 2 of `#/styles/core/themes`, and 1 of
  `#/hooks/use-media-query` (from `components/charts/stories/spark-chart.stories.tsx`).
  Zero imports of `#/libraries`, `#/api`, `#/routes`, or any other app code —
  the boundary is already clean.
- `src/styles/` has three groups: `core/` (5 files, the design tokens —
  consumed by components 350+ times), `element/` (3 app-layout style files)
  and `pages/` (3 app-page style files). `element/` and `pages/` import
  `#/styles/core/*` 18 times.
- Webapp consumers of `#/components`: 6 route files
  (`src/routes/index.tsx`, `src/routes/__root.tsx`,
  `src/routes/(app)/settings.tsx`, `src/routes/(app)/overview.tsx`,
  `src/routes/(auth)/login.tsx`, `src/routes/(auth)/forgot-password.tsx`) and
  3 test files (`tests/setup-test.ts:31` mocks `#/components/theme`,
  `tests/setup-browser.ts:28` same, `tests/helpers.tsx:4` imports
  `ThemeProvider`). Storybook: `.storybook/decorator.tsx:3` imports
  `#/components/base/provider`.
- Theme is duplicated: `src/theme/` and `src/components/theme/` are tracked,
  byte-identical (7 files each, `diff -rq` clean). Four files import
  `#/theme` (`src/routes/(app)/settings.tsx`,
  `src/routes/(app)/-sidebar.tsx`, `src/routes/(auth)/route.tsx`,
  `.storybook/decorator.tsx:4`); `tests/helpers.tsx` must import
  `#/components/theme` because the duplicate module identity triggers a
  deterministic `ScriptOnce` failure in the home test (recorded in memory,
  insight `01a117f8bb83j41o`). The extraction removes the duplication and
  the workaround with it.
- External packages the components use (import counts inside
  `src/components`): `@stylexjs/stylex` 229, `@stylexjs/atoms` 69,
  `@tanstack/react-table` 25, `@tanstack/charts` (+ subpaths) ~40,
  `@base-ui/react` (several subpaths), `@keyline-icons/react` 37,
  `@dnd-kit/*` 7, `@tanstack/react-virtual` 1, `@tanstack/react-hotkeys` 1,
  `react-day-picker` 2, `react-phone-number-input` 1,
  `react-resizable-panels` 2, `country-flag-icons` 1, `date-fns` 1. Stories
  additionally use `@storybook/tanstack-react` (90 files) and
  `storybook/test` (78). Components use none of: `@tanstack/react-form`,
  `@tanstack/react-query`, `@tanstack/react-store`, `@connectrpc/*`, `ofetch`,
  `zod`, `@simplewebauthn/browser`, `blobatar`, `comlink`, `@date-fns/tz`.
- Workspace consumption idiom already exists: `packages/plugins/package.json`
  exposes TS source via `"exports": { "./plugin-golang": "./plugin-golang.ts" }`
  and `packages/webapp/package.json` declares `"plugins": "workspace:*"`;
  `packages/webapp/vite.config.ts:8` imports `plugins/plugin-golang`. The new
  package follows the same shape.
- Toolchain touchpoints: `.storybook/main.ts:8` story glob
  `'../src/**/*.stories.@(mdx|jsx|tsx)'`; webapp `vite.config.ts` defines the

- `packages/e2e-tests/` has zero references to components or styles (verified

- No migration, database, Go, or API surface is touched by this plan.

## Decisions

- **D1 (owner, 2026-10-08) — Scope: components + core styles.**
  `src/components/**`, `src/styles/core/**`, and `src/hooks/use-media-query` move
  to `packages/components`. Rejected: components-only (the package would
  import webapp internals through a cross-package alias — rule 73 forbids
  exactly that, and reuse dies); separate `packages/tokens` (a third package
  for 5 files with a single consumer today — surface without payoff; can be
  split later if a second consumer needs tokens without components).
- **D2 (owner; amended 2026-10-08, owner structure correction) — Source-sharing
  consumption.** The package ships TSX source; each consumer compiles it with
  its own pipeline (StyleX unplugin already transforms the module graph). The
  package owns `vite.config.ts` — but only for its own Storybook and vitest
  pipeline (stories live in the package); it does not compile or publish
  output. Rejected: compiled output (a build pipeline, `.d.ts` generation, and
  a second StyleX configuration for consumers to maintain).
- **D3 (owner, 2026-10-08; corrected same day) — Package name and directory
  `uilibs`.** `packages/uilibs/`, bare name `uilibs`. The owner's correction
  also fixes the internal layout (D4). Rejected: `components` (the initial
  choice — superseded), `@saka/components` (no scoped name exists in this
  workspace).
- **D4 (agent; amended 2026-10-08, owner structure correction) — Package
  layout and import rules.** The package layout is the owner's:
  `packages/uilibs/src/{components/{base,charts,extra,icons},hooks,styles,theme}`
  with `styles/` flat (no `core/` subfolder), theme at the top level (not
  under components), and the package's own `.storybook/`. Inside the package,
  imports are RELATIVE only — the `#/*` alias stays package-private
  scaffolding but no module uses it, because a consumer's StyleX unplugin
  resolves `#/*` to the consumer's own src (P2 lesson). Cross-package imports
  use the package specifier (`uilibs/components/base/button/…`).
  Rejected: re-nesting or flattening beyond the owner's shape (churn without
  gain); `#/*` self-imports inside the package (breaks under the consumer's
  unplugin alias).
- **D5 (agent) — Theme unification.** The package's `src/theme/` (top level,
  per the owner's layout) is the single theme; webapp's duplicate `src/theme/`
  is deleted and its four importers re-pointed; `tests/helpers.tsx` drops the
  `#/components/theme` workaround and imports the package, with the
  `vi.mock` module ids in `tests/setup-test.ts` / `setup-browser.ts` updated
  to the same specifier. This deletes the known ScriptOnce trap instead of
  porting it. Rejected: keeping both copies (two module identities for one
  component is the bug this plan exists to kill).
- **D6 (agent; amended twice, final form) — Real workspace dep with source
  exports.** `packages/uilibs/package.json` exposes
  ```json
  "exports": { "./*": ["./src/*", "./src/*/index.ts", "./src/*/index.tsx", "./src/*.ts", "./src/*.tsx"] }
  ```
  Webapp declares `"uilibs": "workspace:*"` and imports
  `uilibs/components/base/button/…`. Rejected: a cross-package tsconfig path
  alias (rule 73 forbids it). Package-internal imports are relative only —
  the webapp StyleX unplugin resolves `#/*` to webapp's own src, so a package
  file must never import through `#/*`.
  Amendment record (both settled by experiment, 2026-10-08): TS bundler
  resolution probes every entry of an exports fallback array but never
  index-resolves a directory target; vite (vite-plus core) resolves only the
  FIRST array entry but index- and extension-infers it. Hence the raw
  `./src/*` target first (vite), index/extension entries after (TS). A
  `types`-condition object, `typesVersions`, and any single-template map
  were all tried and rejected.
- **D7 (agent) — Component stories move with the code; webapp unit tests
  stay.** Stories are the components' documentation and live next to them;
  webapp's `tests/` exercises the webapp composition and only 3 of its files
  reference components (re-pointed, not moved). A `components` vitest project
  is added only when the package grows its own tests (rule 74).

## Shape and enforcement points

- New package: `packages/uilibs/` (owner's layout, D3/D4):
  ```
  packages/uilibs/
    .storybook/          # moved from webapp; owns the storybook + vitest pipeline
    src/
      components/{base,charts,extra,icons}
      hooks/
      styles/            # flat: tokens, colors, utils, popup, themes (no core/)
      theme/
    package.json         # name uilibs; source exports map per D6
    tsconfig.json        # extends tsconfig.base.json; owns #/* → ./src/*
    vite.config.ts       # stylex unplugin + react compiler + storybook vitest project
  ```
  Stories and their devDependencies live in the package. No compiled output
  (D2).
- Enforcement points:
  - `packages/webapp/tsconfig.json` keeps `#/*` for webapp only; webapp code
    reaches the library only through the `uilibs` package specifier.
  - Inside the package, imports are relative only (D4); no `#/*` in package
    modules (grep-enforced in P3's validation).
  - Root `vite.config.ts` typecheck line gains `tsc -p packages/uilibs --noEmit`
    and its test-project reference gains `packages/uilibs/vite.config.ts`.
  - The webapp storybook scripts, `.storybook/` directory, and the storybook
    vitest project move out of webapp; webapp keeps its unit/browser projects.
  - `pnpm-workspace.yaml` already covers `packages/*` (verified) — no change.
- Explicitly untouched: `web/`, `framework/`, `internal/`, `modules/`, `cmd/`,
  `api/`, migrations, `packages/email`, `packages/plugins` (except nothing —
  plugins is only the idiom reference), `packages/e2e-tests` (E2E stays there,
  owner-confirmed).

  carry the suggested commit messages. The standing commit rule (stage
  explicit paths, no push) resumes when the plan completes.

  no migration and no database; nothing to reset, nothing to ALTER.
- **Yaak updates: not applicable** — no endpoint, job, email, audit event,
  guard rule, or settings key ships in this plan.
- Per-phase validation runs before each commit; a phase that fails validation
  does not commit.
- The plan executes only on the owner's explicit instruction.
