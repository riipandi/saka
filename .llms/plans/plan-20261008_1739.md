# Component library extraction to `packages/components`

## Objective

Make the UI component set reusable by future packages: extract
`packages/webapp/src/components/` (plus the design tokens it cannot live
without) into a workspace package every frontend package can consume, with
atomic commits per phase. This implements the independent-packages rule the
tree already commits to — `.llms/rules.md` line 72 ("a new frontend package is
one directory with its own config, not another root clause"), line 73
(per-package tsconfig ownership), and line 74 (a vitest project exists only
when a surface has tests).

## Current state

Every claim below was verified in the tree on 2026-10-08.

- `packages/webapp/src/components/` holds 316 `.ts`/`.tsx` files in five
  subdirectories: `base/`, `charts/`, `extra/`, `icons/`, `theme/`. 90 of them
  are `*.stories.tsx`. There are no co-located `*.test.*` files.
- The only webapp-internal code the components import is design styling and
  one hook: 236 imports of `#/styles/core/tokens.stylex`, 103 of
  `#/styles/core/colors.stylex`, 11 of `#/styles/core/utils.stylex`, 8 of
  `#/styles/core/popup.stylex`, 2 of `#/styles/core/themes`, and 1 of
  `#/hooks/use-media-query` (from `components/charts/stories/spark-chart.stories.tsx`).
  Zero imports of `#/libraries`, `#/api`, `#/routes`, or any other app code —
  the boundary is already clean.
- `src/styles/` has three groups: `core/` (5 files, the design tokens —
  consumed by components 350+ times), `element/` (3 app-layout style files)
  and `pages/` (3 app-page style files). `element/` and `pages/` import
  `#/styles/core/*` 18 times.
- Webapp consumers of `#/components`: 6 route files
  (`src/routes/index.tsx`, `src/routes/__root.tsx`,
  `src/routes/(app)/settings.tsx`, `src/routes/(app)/overview.tsx`,
  `src/routes/(auth)/login.tsx`, `src/routes/(auth)/forgot-password.tsx`) and
  3 test files (`tests/setup-test.ts:31` mocks `#/components/theme`,
  `tests/setup-browser.ts:28` same, `tests/helpers.tsx:4` imports
  `ThemeProvider`). Storybook: `.storybook/decorator.tsx:3` imports
  `#/components/base/provider`.
- Theme is duplicated: `src/theme/` and `src/components/theme/` are tracked,
  byte-identical (7 files each, `diff -rq` clean). Four files import
  `#/theme` (`src/routes/(app)/settings.tsx`,
  `src/routes/(app)/-sidebar.tsx`, `src/routes/(auth)/route.tsx`,
  `.storybook/decorator.tsx:4`); `tests/helpers.tsx` must import
  `#/components/theme` because the duplicate module identity triggers a
  deterministic `ScriptOnce` failure in the home test (recorded in memory,
  insight `01a117f8bb83j41o`). The extraction removes the duplication and
  the workaround with it.
- External packages the components use (import counts inside
  `src/components`): `@stylexjs/stylex` 229, `@stylexjs/atoms` 69,
  `@tanstack/react-table` 25, `@tanstack/charts` (+ subpaths) ~40,
  `@base-ui/react` (several subpaths), `@keyline-icons/react` 37,
  `@dnd-kit/*` 7, `@tanstack/react-virtual` 1, `@tanstack/react-hotkeys` 1,
  `react-day-picker` 2, `react-phone-number-input` 1,
  `react-resizable-panels` 2, `country-flag-icons` 1, `date-fns` 1. Stories
  additionally use `@storybook/tanstack-react` (90 files) and
  `storybook/test` (78). Components use none of: `@tanstack/react-form`,
  `@tanstack/react-query`, `@tanstack/react-store`, `@connectrpc/*`, `ofetch`,

- Workspace consumption idiom already exists: `packages/plugins/package.json`
  exposes TS source via `"exports": { "./plugin-golang": "./plugin-golang.ts" }`

- Toolchain touchpoints: `.storybook/main.ts:8` story glob

- `packages/e2e-tests/` has zero references to components or styles (verified

- No migration, database, Go, or API surface is touched by this plan.

## Decisions

- **D1 (owner, 2026-10-08) — Scope: components + core styles.**
  `src/components/**`, `src/styles/**`, and `src/hooks/use-media-query` move
  to `packages/components`. Rejected: components-only (the package would
  import webapp internals through a cross-package alias — rule 73 forbids
  exactly that, and reuse dies); separate `packages/tokens` (a third package
  for 5 files with a single consumer today — surface without payoff; can be
  split later if a second consumer needs tokens without components).
- **D2 (owner, 2026-10-08) — Source-sharing consumption.** The package ships
  TSX source; each consumer compiles it with its own pipeline (StyleX unplugin
  already transforms the module graph). Rejected: compiled output (a build
  pipeline, `.d.ts` generation, and a second StyleX configuration to maintain
  for zero current consumers).
- **D3 (owner, 2026-10-08) — Package name `components`.** Bare name, matching
  `webapp`, `email`, `plugins`, `e2e-tests`. Rejected: `@saka/components`
  (no scoped name exists in this workspace).
- **D4 (agent) — Preserve subpaths; one rewrite family.** The moved tree keeps
  its shape (`packages/components/src/{base,charts,extra,icons,theme,styles,hooks}`),
  so inside the package only `#/components/X` → `#/X` rewrites are needed;
  `#/styles/core/X` and `#/hooks/use-media-query` keep working unchanged under
  the package's own `#/*` alias. Rejected: re-nesting or flattening
  directories during the move (churn that makes the diff unreviewable).
- **D5 (agent) — Theme unification.** The package's `src/theme/` is the single
  theme; webapp's duplicate `src/theme/` is deleted and its four importers
  re-pointed; `tests/helpers.tsx` drops the `#/components/theme` workaround
  and imports the package. This deletes the known ScriptOnce trap instead of
  porting it. Rejected: keeping both copies (two module identities for one
  component is the bug this plan exists to kill).
- **D6 (agent) — Real workspace dep with source exports.**
  `packages/components/package.json` gets
  `"exports": { "./*": "./src/*" }`; webapp declares
  `"components": "workspace:*"` and imports `components/base/button/…`.
  Rejected: a cross-package tsconfig path alias (rule 73 forbids it).
  Fallback if TS/Vite rejects the extensionless map: explicit per-extension
  export keys, same as `plugins` does.
- **D7 (agent) — Component stories move with the code; webapp unit tests
  stay.** Stories are the components' documentation and live next to them;
  webapp's `tests/` exercises the webapp composition and only 3 of its files
  reference components (re-pointed, not moved). A `components` vitest project
  is added only when the package grows its own tests (rule 74).

## Shape and enforcement points

- New package: `packages/components/` with `package.json` (name `components`,
  `exports: { "./*": "./src/*" }`, dependencies carved from the usage census
  above, storybook packages as devDependencies), `tsconfig.json` extending
  `tsconfig.base.json` with `"paths": { "#/*": ["./src/*"] }` and its own
  `include`, and `src/` as the moved tree. No `vite.config.ts` — the package
  has no pipeline of its own (D2).
- Enforcement points:
  - `packages/webapp/tsconfig.json` keeps `#/*` for webapp only; webapp code
    reaches the library only through the `components` package specifier.
  - Root `vite.config.ts` typecheck line gains `tsc -p packages/components --noEmit`.
  - `.storybook/main.ts` story glob gains the package path; the webapp
    storybook vitest project keeps compiling the moved stories through the
    same `.storybook` configDir.
  - `pnpm-workspace.yaml` already covers `packages/*` (verified) — no change.
- Explicitly untouched: `web/`, `framework/`, `internal/`, `modules/`, `cmd/`,
  `api/`, migrations, `packages/email`, `packages/plugins` (except nothing —
  plugins is only the idiom reference), `packages/e2e-tests`.
