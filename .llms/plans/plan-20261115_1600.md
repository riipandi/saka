# The sidebar spends less height — dense rows and groups that fold

## Objective

The sidebar's navigation runs out of viewport before the menu runs out of items: at the current metrics the seventeen items and four group labels need about 890px below the header, and a 1080p laptop already scrolls. The owner picked option 2 on 2026-11-15: tighten the metrics with the tokens the design system already has, and let each administration group fold, its state remembered per group. No token, color, or component is added to `packages/uilibs`; the tooltip the collapsed (icon-only) mode gained in `1580c2c9` stays.

## Current state (verified in the tree, 2026-11-15)

- **Row and label metrics** (`packages/webapp/src/styles/element/sidebar.stylex.ts`): `navItem` is `2.5rem` tall with `gap: unit.x3` and `paddingInline: unit.x3`; `navContent` stacks rows with `gap: unit.x1` and `paddingInline: unit.x3`; `sectionLabel` carries `paddingTop: unit.x4`, `paddingBottom: unit.x1`, `fontSize.caption1` (line 1rem). One row is 44px, one label 36px; the sum for the seeded administrator is about 890px.
- **The collapsed (icon-only) mode** uses `navItemCollapsed` at `2.5rem` square, a `divider` between groups, and a right-side `Tooltip` per item (`-sidebar.tsx`, `1580c2c9`). The sidebar width is `15rem` expanded, `3.75rem` collapsed, `18rem` on the small breakpoint (`containerExpanded`, `containerCollapsed`).
- **Groups are static.** `adminGroups` (`-sidebar.tsx`) is a flat array of `{label, items}`; `renderNavItems` maps each group under a `<p>` label. Nothing folds, nothing is remembered per group.
- **The store already persists one sidebar fact.** `libraries/app.store.ts` keeps `sidebarCollapsed` in a TanStack store hydrated from `localStorage['app.sidebarCollapsed']`, with `toggleSidebarCollapsed`. The same file is where a per-group state belongs.
- **`uilibs` carries the fold primitive.** `components/base/collapsible` (`Collapsible`, `CollapsibleTrigger`, `CollapsibleContent`) animates height through `--collapsible-panel-height` with the reduced-motion guard (`collapsible.stylex.ts`). No new component is needed.
- **Tests that read the sidebar:** `packages/webapp/tests/page/admin-shell.browser.test.tsx:126-177` mounts `SideNavbar` and asserts the group label and the item links are visible for an administrator snapshot. E2E workflows (`admin-console.test.ts` and the others) navigate by URL or by link name inside the sidebar; a folded group would hide those links.
- **Prose that describes the sidebar:** `.llms/architecture.md:1093` (D2/D7, "renders a domain group only when at least one of its items passes"), `.llms/rules.md:32` (admin console frontend), `docs/product-guide.md:99` and `docs/users.md:5` (the Administration section).

## Decisions

- **D1 (owner pick 2026-11-15): dense metrics plus foldable groups.** Rejected: density alone (does not scale when the menu grows) and a scroll affordance alone (accepts the problem).
- **D2: the metrics come from the existing scale, no new token.** Row height `2rem`, `navContent` gap `unit.x1`, item `gap: unit.x2` (the scale has no `x2_5`), icon `1rem`, `sectionLabel` padding `unit.x3` top and `unit.x0_5` bottom, `navContent` `paddingInline: unit.x2`. A row becomes 36px and a label 28px: about 740px for the same menu, 150px saved before any group folds. The collapsed mode's square follows to `2rem` and the header's collapse trigger keeps its own size. Rejected: a smaller font (`caption1` for items) — legibility is the wrong thing to spend.
- **D3: a group header is a button that folds its panel; groups start open.** The label `<p>` becomes a `CollapsibleTrigger` carrying the label and a trailing chevron (`ChevronDown` from `@keyline-icons/react`, rotated when open — the set is already a dependency and `uilibs` calendar uses the glyph), styled with the existing `sectionLabel` type. Default is open, so a fresh browser, the unit tests, and the E2E workflows see every link exactly as today. Rejected: starting closed (hides the console from a first-time administrator; breaks every test that clicks a link) and an accordion (one group open at a time — an administrator works across groups).
- **D4: the state lives in `app.store` as a set of closed group labels, persisted under `localStorage['app.sidebarClosedGroups']`.** Closed, not open, is stored, so a new group ships open without a migration of the stored value. The group that contains the active route renders open regardless of the stored state and is not written back — the fold is a preference, the current page is a fact. Rejected: `sessionStorage` (the preference should outlive a tab) and per-group URL state (not navigation state).
- **D5: the icon-only mode does not fold.** With no labels there is nothing to fold under; the divider between groups stays and every item renders, as today. Rejected: hiding closed groups' icons (an icon rail that changes shape with a preference the user cannot see).
- **D6: the small breakpoint (the mobile drawer) folds the same way.** The drawer renders the expanded layout; the same store state applies. No separate mobile rule.

## Execution rules

- Atomic commit per phase is authorized for this plan; each phase heading names its suggested commit message. A commit stages that phase's explicit paths only (`git status` first) — never `git add -A` or `git add .`.
- When the last phase lands, the agent stops, reports, and recommends the closing commit message with its paths. The standing commit rule resumes.
- Frontend-only: no migration, no proto, no Yaak row, no `rpc:stale` drift expected; the final phase confirms the last two.
- No new token, color, or `uilibs` component; the design system stays as it is.
- Per-phase validation runs before each commit. Test names stay behavioral; fixtures follow the Dan Brown / Harry Potter list in `.llms/rules.md`.
- The plan executes only on the owner's explicit instruction.

## Explicitly out of scope

- New tokens, colors, or components in `packages/uilibs`.
- An accordion (one open group at a time).
- Folding or hiding groups in the icon-only mode.
- Moving items between groups or reordering them (the owner kept the order on 2026-11-15; only the three group names were shortened); adding a search box to the sidebar (the command palette already exists).
- Server-side persistence of the preference.
