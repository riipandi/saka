# Plan — Comprehensive Webapp Navigation, Information Architecture, and UI/UX Refinement

## Objective

Deliver an end-to-end user experience (UX) and visual refinement across the entire [packages/webapp](file:///Users/ariss/Developer/github.com/riipandi/saka/packages/webapp) by overhauling the bloated menu/route architecture, maximizing component adoption from [packages/uilibs](file:///Users/ariss/Developer/github.com/riipandi/saka/packages/uilibs), and strictly cleaning up styling inconsistencies (purging rogue Tailwind utility classes in favor of StyleX).

### Deep Route & Information Architecture (IA) Analysis:
The current route layout presents significant cognitive friction:
1. **Sidebar Bloat & Lack of Grouping**:
   - The current sidebar (`-sidebar.tsx`) dumps **14 distinct items** into a single flat "Administration" list and **9 items** into "Account". Users must scan through a wall of ungrouped icons.
   - Administration items are logically disparate: user provisioning (`Users`, `Groups`, `Signup tokens`), edge security (`Blocklist`, `Audit trail`, `Consents`), developer APIs (`OIDC clients`, `Webhooks`, `API keys`, `Custom claims`, `OAuth providers`), and system administration (`Platform settings`, `Notifications`, `Roles`).
   - Grouping these into 4 clear functional domains:
     - **Identity & Access**: Users, User Groups, Roles & Permissions, Consents.
     - **Security & Activity**: Audit Trail, Blocklist, Signup Tokens, Security Policies.
     - **Developer & Integrations**: OIDC Applications, Outbound Webhooks, System API Keys, Custom Claims, OAuth SSO Connections.
     - **Platform & System**: Platform Settings, Broadcast Notifications.
2. **Account vs Administration Separation**:
   - The top header (`(app)/route.tsx`) lacks a cohesive application header. User profile avatar, account switching/settings, and theme switcher are cramped at the very bottom of the sidebar or hidden.
   - Moving the authenticated user avatar and quick settings into a top-right User Menu (`DropdownMenu` / `Popover`) aligns with standard modern productivity applications (Linear, Clerk, WorkOS, Apple/Emil design principles).
3. **Misalignment of UI Primitives in Every View**:
   - Tabular multi-column datasets (Audit logs, API keys, Webhook deliveries, Users, Blocklists, Tokens) are rendered in vertical card stacks (`ItemGroup` / `Item`), destroying scannability and wasting 60% of horizontal screen space.
   - Pagers are hand-rolled as simple flex buttons (`Previous` / `Next`) rather than using semantic `Pagination` (`uilibs/components/extra/pagination`).
   - Row action buttons are crowded inline instead of consolidated into `DropdownMenu` ("...").
   - Detail pages (`/admin/users/$id`, `/admin/webhooks/$id`, `/admin/oidc-clients/$id`) use unstructured `<div>` tags instead of `DescriptionList` (`<dl>`, `<dt>`, `<dd>`).
4. **Styling Inconsistencies & Leaked Tailwind Classes**:
   - Raw Tailwind utility classes (`className='flex flex-col gap-2'`, `className='font-mono text-xs'`) were inadvertently introduced in several files (`-oidc-client-form.tsx`, `-client-preview-drawer.tsx`, `-scim-provider-card.tsx`, `-show-once-secret-dialog.tsx`, `-client-secrets-dialog.tsx`), causing styling fragility with the StyleX pipeline.

## Decisions

### D1: Information Architecture & Sidebar Taxonomy Refactoring
- **Decision**: Restructure `-sidebar.tsx` into categorized collapsible/distinct sections:
  1. **Core**: Overview (`/overview`).
  2. **Identity & Access**: Users (`/admin/users`), Groups (`/admin/groups`), Roles (`/admin/roles`), Consents (`/admin/consents`).
  3. **Security & Governance**: Audit Trail (`/admin/audit`), Blocklist (`/admin/blocklist`), Signup Tokens (`/admin/signup-tokens`).
  4. **Developer & Integrations**: OIDC Clients (`/admin/oidc-clients`), Outbound Webhooks (`/admin/webhooks`), API Keys (`/admin/api-keys`), Custom Claims (`/admin/claims`), OAuth Providers (`/admin/oauth-providers`).
  5. **Platform Settings**: Settings (`/admin/settings`), Notifications (`/admin/notifications`).
  - Personal Account items (`/settings`, `/account/*`) can be directly navigated from the User Profile Menu in the top header or retained cleanly under an "Account" group.
- **Rationale**: Eliminates endless scrolling and hunting through 14 items, grouping related tasks logically.
- **Alternatives rejected**: Flat unorganized list (poor readability).

### D2: Unified Top Header with User Menu & Notification Popover
- **Decision**: Elevate `(app)/route.tsx` top bar to feature:
  - Global `Breadcrumb` tracking the active page hierarchy.
  - Global Search trigger (`Command` palette `⌘K`).
  - `NotificationBell` with `Popover` flyout showing the latest 5 unread notifications and "View all" link.
  - User Avatar with `DropdownMenu` ("Profile & Settings", "Security", "Active Sessions", "Sign out").
- **Rationale**: Follows standard modern application design, reducing sidebar clutter and providing immediate access to personal account controls from any screen.

### D3: Full Adoption of Semantic Table for Structured Entities
- **Decision**: Refactor all multi-attribute list views from `ItemGroup`/`Item` to `Table` (`Table`, `TableHeader`, `TableRow`, `TableCell`):
  - Admin Audit Logs (`/admin/audit`)
  - Outbound Webhook Delivery Attempts (`/admin/webhooks/$id`)
  - Platform API Keys overview (`/admin/api-keys`)
  - User Directory (`/admin/users`)
  - Blocklist Rules (`/admin/blocklist`)
  - Signup Tokens (`/admin/signup-tokens`)
- **Rationale**: Restores tabular structure, horizontal alignment, scannability, and sorting headers.

### D4: Consolidation of Row Actions with DropdownMenu
- **Decision**: Replace crowded inline action buttons with a standard `DropdownMenu` trigger on each table and item row.
- **Rationale**: Declutters the UI, highlights only the primary CTA, and safeguards destructive actions.

### D5: Strict Tailwind Purge in favor of StyleX
- **Decision**: Cleanse all rogue `className='...'` occurrences in webapp components, converting them into typed StyleX declarations (`stylex.create(...)` and `stylex.props(...)`).
- **Rationale**: Ensures bulletproof theme consistency and compliance with repo styling rules.
