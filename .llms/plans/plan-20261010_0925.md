# Wave 1.6 — frontend observability

## Objective

Land `.llms/integration-roadmap.md` Wave 1.6 ("frontend observability", owner
direction 2026-10-10): the SPA contributes traces to the same OTLP/HTTP
collector story the backend already runs — a web tracer named after the
deployment, client spans at the `authFetch` seam, a span per navigation,
query-string redaction before export, and the worker's auth RPCs joined into
the traces that caused them — all opt-in through the deployment document. The
seven roadmap checkboxes under the wave head are the rows this plan closes;
the sixth's open decision (blocker #8, where the browser dials) is settled
below as D1.

The reference is the damikun workshop article (read 2026-10-10, recorded in
the roadmap): the provider mount, the ignore-own-exports posture, the wire
shape, and the collector-behind-a-proxy option are adopted; the fetch
monkey-patching, the zone context manager, and the `SimpleSpanProcessor` demo
shortcut are rejected. Pocket ID's package set (`@opentelemetry/api`,
`sdk-trace-web`, `resources`, `semantic-conventions`,
`exporter-trace-otlp-http`) is the reference dependency list.

## Decisions

- **D1 (2026-10-10, owner pick 1) — the browser's collector is a public
  configuration field.** `OTEL` gains a `Browser` section
  (`otel.browser.endpoint`, `otel.browser.ratio`) published in the **public**
  scope of `GET /api/configuration`; an empty endpoint means frontend
  tracing is off (`omitzero` omits the section entirely). The browser dials
  the collector directly, cross-origin; the collector's receiver answers the
  CORS check (D2). Rejected: the same-origin Go proxy (a second backend
  surface — handler, timeouts, config key — and a permanent public path
  contract for what is a deployment address); the build-time variable
  (rebuild to move a collector, and a second source of truth that breaks the
  "no hard-coded capability" rule Wave 0 built); reusing `otel.endpoint`
  (the process's export address is often loopback-only and carries the
  process's auth headers — not a browser's door).
- **D2 (2026-10-10) — the collector answers the CORS check; the compose
  config carries it.** The `otlp` http receiver in
  `container/otel-collector.yaml` gains `cors.allowed_origins` for the dev
  origin (`http://localhost:3000`). In production the operator fronts the
  collector the same way they front any OTLP receiver; the config's
  `browser.endpoint` names whatever URL answers. No Go routing changes.
- **D3 (2026-10-10) — one span per request, opened at the `authFetch`
  seam.** The seam records an HTTP client span (semconv `http.request`
  conventions: method, url full/path, status), injects `traceparent` from
  the active context, and sets the span's status from the response — a
  refusal is an error, as the backend's own middleware treats one. Both the
  REST `fetcher` and the Connect transport get it from the one seam.
  Rejected: `FetchInstrumentation`/`instrumentation-xml-http-request`
  (monkey-patching `window.fetch` the roadmap rejected), instrumenting the
  Connect transport separately (two points where one seam exists), spans in
  `withAuth`'s refresh/replay (the refresh is the engine's business, D4).
- **D4 (2026-10-10) — the worker joins through the facade, never
  instruments independently.** The main-thread facade wrapper records one
  span around each user-caused operation (`login`, `continueSignIn`,
  `refresh`, `maybeRefresh`, `restore`, `session`, `logout`) and passes the
  active `traceparent` into the call; the engine's transport merges it into
  the request headers the way `deviceHeaders` already travel. The plumbing
  calls (`accessToken`, `authorization`) stay uninstrumented — they are
  sub-steps of the seam, not operations. Rejected: a second tracer provider
  inside the worker realm (double exports, two resources, the worker would
  report as its own service); a mutable "current context" message (races
  concurrent calls); per-call spans for the plumbing (noise, not signal).
- **D5 (2026-10-10) — the sampler is parent-based ratio, riding the public
  field.** `otel.browser.ratio` feeds a `ParentBased(TraceIDRatioBased(r))`
  sampler: a trace the backend already sampled keeps the browser's half
  whole. A configured endpoint with a zero `ratio` samples **everything** —
  the loud default, because an operator who named a collector wanted spans;
  a silent zero would sample nothing. When the endpoint is empty the tracer
  never initializes: no provider, no exporter, no queue.
- **D6 (2026-10-10) — redaction is written once, at the processor seam.** A
  single `SpanProcessor` on the export path does both jobs before any span
  leaves: it strips the query string from every URL attribute (the reset
  token, the one-time-access code, and the OAuth flow token travel in search
  params and none may reach a collector) and drops any span whose target is
  the telemetry endpoint itself or a non-first-party origin (the
  ignore-own-exports posture). Not per-span call sites — one processor,
  testable in isolation.
- **D7 (2026-10-10, roadmap owner direction) — metrics and logs stay
  backend-only.** The browser contributes traces; console-error capture and
  client metrics wait for a named need.
- **D8 (2026-10-10) — lazy initialization after first paint, off the
  critical path.** The provider mounts in `__root.tsx` beside the other
  providers but initializes on an idle callback after the config document
  has answered; when tracing is off it resolves to nothing. The resource
  names the SPA from constants the public document cannot supply:
  `service.name` = `saka-web` (the process's `service_name` is
  administrator-scope and not published), `deployment.environment.name` =
  the public `app.mode` (`publish.go:315` publishes it anonymously). The
  tracer is the SDK's own; `WebTracerProvider` is the base for the
  document-context the seam needs.

### Phase 2 — the web tracer foundation: resource, sampler, exporter, redaction

The OTel packages join `packages/webapp/package.json` (the Pocket ID
reference set: `@opentelemetry/api`, `sdk-trace-web`,
`exporter-trace-otlp-http`, `semantic-conventions`). New
`packages/webapp/src/libraries/telemetry/`:

- `telemetry.ts` — `initializeWebTracing(config)` builds the provider: the
  resource (`service.name` = `saka-web`, `deployment.environment.name` =
  `app.mode`, `service.version` from the build), the D5 sampler, a
  `BatchSpanProcessor` feeding the OTLP/HTTP trace exporter pointed at
  `browser.endpoint` (path defaults to the protocol's `/v1/traces`), and
  the D6 redaction processor in front of the batcher. Registers the global
  tracer + the W3C `TraceContext` propagator and resolves a shutdown
  handle. Idempotent: a second call is a no-op.
- `TelemetryProvider` — mounts in `__root.tsx` beside the other providers;
  reads the config store, schedules the init on an idle callback after
  first paint, and renders nothing itself. Off = no provider, no exporter,
  no queue, no cost.

Unit tests: the redaction processor (query strings stripped, own-exports and
non-first-party targets dropped, non-URL spans untouched), the sampler
mapping (zero ratio = always), the off path (no global provider installed),
the idempotence. A browser test mounts the provider with tracing off and on
against an in-memory exporter and asserts the app renders identical in both.

Suggested commit: `feat(webapp): the web tracer foundation`

- Validation: `pnpm -C packages/webapp exec vp test --project unit`;
  `--project browser`; tsc; `task lint`.

### Phase 3 — spans at the seam: one client span per authFetch request

Inside `authFetch`, the request's send wraps in a span on the active
context: name `HTTP <method>` per the client conventions, attributes
`http.request.method`, `url.full`/`url.path` (the D6 processor handles the
query before export), the `traceparent` header injected from the span
context, and on response the `http.response.status_code` attribute plus the
span status — a non-2xx or a refused envelope marks the span `Error` with a
brief status message. The replay after a 401 is part of the same logical
operation but gets its own span (each is a real HTTP request); the refresh
that caused it is the engine's (D4). Third-party origins (the seam never
sends them today, but the guard is the D6 drop, not a promise about
callers) and the telemetry endpoint never span.

Unit tests with a fetch stub: the span opens and closes with the
attributes, the `traceparent` header rides the request, a 500 and a 401
mark the status, the off path sends no `traceparent` and costs nothing.

Suggested commit: `feat(webapp): client spans at the auth seam`

- Validation: `--project unit`; `--project browser`; tsc; `task lint`.

### Phase 4 — navigation spans and the worker joins the trace

Two closures:

- **Navigation**: the root route's router lifecycle opens one span per
  navigation, named by the route id (`nav /settings`), started at
  `onBeforeLoad` and ended at `onResolved` (the load error path ends it as
  `Error`). The child-of relationship is real: the seam's request spans
  fired during the navigation become its children.
- **The worker**: the main-thread facade wrapper spans each user-caused
  operation and passes `traceparent` through the call; the engine's
  transport merges it into the request headers beside `deviceHeaders`
  (D4). The plumbing calls stay uninstrumented. The worker realm never
  imports the SDK.

Unit tests: the router span opens and closes per navigation with the route
id; the facade wrapper produces the span and the engine's transport merge
sees the header (a stubbed engine records what arrived); the plumbing calls
produce none.

Suggested commit: `feat(webapp): navigation spans and the worker joins the trace`
