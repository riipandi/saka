# Plan: Upgrade connect-go to v2

## Objective

Migrate the Go transport from `connectrpc.com/connect` v1 to
`connectrpc.com/connect/v2` in full — no backward compatibility, no v1 residue.
The owner's instruction set (2026-10-09): plan first, execution waits for the
owner's explicit go; atomic commit per phase with self-standing commits allowed
during the session; no load tests unless asked; E2E only where relevant; docs
sync and handover mandatory.

References read for this plan: the Buf blog post
`buf.build/blog/connect-go-v2` (2026-10-07), `docs/v2-migration.md`, and
`docs/v2-guide.md` at tag `v2.0.0`.

The migration ships **zero new surface**: no new procedure, REST route, job,
email, audit event, guard rule, or settings key. The wire protocol is
unchanged (v2 changes the Go API only), so the Yaak collection and the
endpoint reference are untouched by design — verified per phase, not edited.

## Decisions

- **D1 (2026-10-09) — Do not preserve v1's unbounded read default.** The
  migration tool pins `WithReadMaxBytes(0)` to keep v1 behavior; rejected.
  This surface already sets an explicit bound
  (`server.max_request_bytes` → `WithReadMaxBytes`), so the option migrates as
  `connecthttp.WithReadMaxBytes(maxRequestBytes)` and the v2 4 MiB default
  never applies. Rejected alternative: the tool's pin — it would silently
  reintroduce unbounded buffering.
- **D2 (2026-10-09) — Rewrite the custom seams to v2 shapes, not around
  them.** (a) `rpcJSONCodec` becomes a v2 stream-oriented codec
  (`MarshalWrite`/`UnmarshalRead` with `context.Context`, `io.Writer`/`io.Reader`),
  registered via `connecthttp.WithCodecs(...)` — which **replaces** the
  defaults, so `connectproto.NewBinaryCodec()` is listed beside the two JSON
  names. (b) The Guard interceptor becomes a `connect.ServerInterceptor` that
  wraps the `ServerStream` and enforces on the first `Receive` of the request
  message (the same hook `validate` uses), preserving the guard-runs-before-
  contract rule. (c) `WithRecover` is gone in v2 — recovery becomes a
  `ServerInterceptor` placed outermost, catching panics from every inner
  interceptor, mapping to `CodeInternal` with the panic value unpublished. (d)
  Interceptor order on `connect.NewServer`: recovery, Guard, validate, otel —
  the v1 relative order preserved. Rejected alternative: keeping v1 running
  beside v2 — the owner forbade backward compatibility.
- **D3 (2026-10-09, revised in P1 the same day) — Ecosystem packages: the
  `/v2` modules were never tagged** (`go list -m -versions`: only the core
  `connect/v2` exists). validate v0.9.0 and otelconnect v0.12.0 carry the v2
  API (`NewServerInterceptor`) on their existing paths — adopted.
  `connectrpc.com/authn` was **dropped** instead of kept: its v0.2.0
  middleware marshals refusals through a v1 `*connect.Error`, and an
  authenticator answering v2 errors made every unauthenticated call answer
  `unknown`/500 (the test run caught it: two connect majors cannot share one
  error type). The bearer middleware is now in-house in
  `internal/transport/middleware/bearer.go` — the same middleware shape, the
  same public-procedure policy, refusal written through
  `connecthttp.NewErrorWriter`; the caller context store and `BearerToken`
  moved to `pkg/jwtutils`. Rejected alternative: keeping authn v0.2.0 — that
  keeps the v1 module in the build and pins the authenticators to v1 errors,
  the backward compatibility the owner refused.
- **D4 (2026-10-09) — Server registration moves to one `*connect.Server`
  mounted once.** `rpcRouter` builds `server := connect.NewServer(interceptors…)`,
  modules register with `Register…Handler(server, svc)` (no per-handler
  options — v2 carries options on the mount), and the router finishes with
  `connecthttp.Mount(r, server, mountOptions…)` on the same chi router, which
  satisfies the `connecthttp.ServeMux` shape (verified at execution; if chi's
  `Router` does not satisfy the interface, a thin adapter is the fix, recorded
  in the phase note). Consequences accepted and documented: (a) `kernel.RPCModule.MountRPC`
  changes to receive the `*connect.Server` (plus the router it mounts on) —
  the per-module options argument dies with v1's per-handler options; (b) v2's
  `Mount` installs a per-service catch-all, so an unknown **method of a known
  service** now answers `unimplemented` in-protocol instead of the plain-text
  404 the per-path registration produced; unknown **services** still reach
  chi's NotFound and the `connecthttp` error writer. (c) `connect.NewErrorWriter`
  → `connecthttp.NewErrorWriter`, built from the mount options, keeping the
  404 / 405 / rate-limit refusals in-protocol. Rejected alternative: keeping
  per-procedure `r.Handle` calls — v2 has no per-handler option vector to
  build them from, and the catch-all is the same boundary in better shape.
- **D5 (2026-10-09) — Error rewrites preserve the wire message, then
  hardening is reviewed, not assumed.** Mechanical pass: `connect.NewError(code,
  errors.New("msg"))` → `connect.NewError(code, "msg")`; `connect.NewError(code,
  err)` → `connect.NewError(code, err.Error()).WithCause(err)` where the
  client-facing text stays. P2 then audits the *new* default: a plain (non-
  `*connect.Error`) return now reaches the client as `CodeUnknown` with no
  message — each such return in handler/service paths is checked for whether
  it was load-bearing (an intended message → author a `*connect.Error`; a
  leak risk → the mask is an improvement, keep it). Rejected alternative:
  blanket `err.Error()` everywhere to keep v1's wire text — that reinstates
  the leak v2 closes.
- **D6 (2026-10-09) — Streaming migration follows the generated types.** The
  WatchNotifications handler takes the generated
  `notificationv1connect.NotificationServiceWatchNotificationsServerStream`;
  the test's receive loop becomes the `msg, err := stream.Receive()` /
  `errors.Is(err, io.EOF)` shape; `stream.Close` after `defer` stays (client
  `Close` is idempotent). Rejected alternative: adopting
  `connectinprocess` for these tests — the router tests exist to exercise the
  full HTTP stack (authn, guard, limits), which in-process bypasses.
- **D7 (2026-10-09) — No load tests in this migration.** The owner's rule
  (now in AGENTS.md, P0): load tests run only when the user asks. The final
  validation uses unit tests, E2E, and a manual serve probe — no k6.

## Execution rules

- **Atomic commit per phase is authorized.** Each phase's commit message is
  named in the phase heading; commits are self-standing and limited to that
  phase's files; the standing commit rule resumes when the plan completes.
  The recommended final message and paths go back to the owner for the
  closing state.
- **No migration in between compiles**: P1 is one commit by construction —
  v2 generated code and the v1 runtime cannot build together. The two-pass
  `connect-go-v2-migrate` flow (buffered in `.output/`, tool installed with
  `go install connectrpc.com/connect/v2/cmd/connect-go-v2-migrate@v2.0.0`)
  runs inside P1.
- **No migration files exist** — this is a dependency migration, not a schema
  change; no `ALTER`, no DB reset applies. The development database is not
  touched by any phase.
- **Yaak updates ride the same change as the contract** — the contract is
  unchanged; the phase note records the verification instead of an edit.
- **Per-phase validation runs before each commit.**
- **E2E is in scope** (owner: mandatory where relevant): the migration's only
  cross-boundary risk is the wire contract the SPA depends on, which the Go
  router tests alone do not close — the Playwright passkey ladder answers it.
- The plan is executed only on the owner's explicit instruction.
