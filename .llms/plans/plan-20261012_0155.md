Key deliverables:
1. **Device login approval** — User-facing approval screen (`DeviceApprovalService/Inspect`, `Decide`) under `/(app)/device.tsx` (over `-device-view.tsx`). Allows an authenticated account holder to inspect an incoming pairing request (User code `XXXX-XXXX`, requesting IP address, user agent, expiration time) and either approve or deny it.
2. **E2E device login client tool** — A standalone Go CLI tool placed in `tools/e2e-device-login/` that exercises the device login protocol end-to-end against the Saka server:
   - Initiates pairing via `POST /api/device-login/requests`.
   - Stores and sends the `saka_device_pairing` cookie.
   - Prints the user code `XXXX-XXXX` and direct verification URL (`/device?code=XXXX-XXXX`).
   - Polls the exchange route `POST /api/device-login/requests/{id}/exchange` until approved or expired.
   - Prints the minted session and authenticated account details upon approval.
3. **Operations console (Ops console)**:
   - **Task Queue administration** (`QueueService`):
     - Route `/(app)/admin/ops/queue.tsx` (over `-queue-view.tsx`).
     - Overview of registered queues (`ListQueues`) with pending and dead task counts.
     - Inspection of pending tasks (`ListTasks`) and dead tasks archive (`ListDeadTasks`).
     - Task detail modal/drawer (`GetTask`) displaying decoded JSON payloads.
     - Operational actions: Cancel unclaimed task (`CancelTask`), Replay dead tasks (`ReplayDeadTasks`), Flush pending tasks (`FlushPendingTasks`), and Flush completed tasks (`FlushCompletedTasks`).
   - **Job Scheduler administration** (`SchedulerService`):
     - Route `/(app)/admin/ops/scheduler.tsx` (over `-scheduler-view.tsx`).
     - Registered jobs listing (`ListJobs`): name, cron expression, next due cursor, and last run timestamp.
     - Manual on-demand execution trigger (`RunNow`) to enqueue tasks immediately without altering the cron schedule.
4. **Parked frontend debts (`TODO(frontend)`)**:
   - `modules/identity/user/service.go:346`: Add timezone preference picker (`User.timezone`) in profile settings (`/settings` over `-settings-view.tsx`), providing an IANA timezone selector defaulting to UTC and browser-detected zone.

## Decisions

### D1: Route layout for Wave 6
- **Decision**:
  - Device approval route: `/device.tsx` on the `(app)` shell (over `-device-view.tsx`).
    - Validates search param `?code=XXXX-XXXX` (optional: pre-fills code input if navigated directly via QR code or link).
    - If no code in URL, renders an OTP-style segmented input or formatted code box.
    - Upon code entry, calls `DeviceApprovalService/Inspect` to display requesting browser facts (IP address, user agent, expiration time).
    - Prompts user with "Approve" (primary CTA) and "Deny" (secondary button), calling `DeviceApprovalService/Decide`.
  - Ops Console admin routes under `/admin/`:
    - `/admin/ops/queue.tsx` (over `-queue-view.tsx`): Tabs for "Queues Overview", "Pending Tasks", and "Dead Archive". Detail drawer for inspecting task payloads.
    - `/admin/ops/scheduler.tsx` (over `-scheduler-view.tsx`): Table of scheduled jobs with `RunNow` button and status badges.
- **Rationale**: Keeps device login intuitive and fast on mobile or desktop; organizes operations under dedicated admin paths.

### D2: Standalone Go E2E client tool (`tools/e2e-device-login`)
- **Decision**: Build a standalone CLI program in `tools/e2e-device-login/main.go` that:
  - Takes flags: `--server` (default `http://localhost:3000`), `--timeout` (default `5m`).
  - Calls `POST /api/device-login/requests`, receives `user_code` and sets `saka_device_pairing` cookie in its cookie jar.
  - Displays formatted banner in terminal:
    ```
    Pairing Code: ABCD-EFGH
    Verification URL: http://localhost:3000/device?code=ABCD-EFGH
    Waiting for approval in browser...
    ```
  - Loops on `POST /api/device-login/requests/{id}/exchange` handling 202 status codes.
  - On 200 OK, prints user profile and success status.
- **Rationale**: Validates the end-to-end device flow across terminal client and web browser without mocking.

### D3: Ops console UI component choices
- **Decision**:
  - Consume `uilibs/components/extra/table` (`Table`) for Queue and Scheduler lists.
  - Use `uilibs/components/base/drawer` (`Drawer`) or `uilibs/components/base/dialog` (`Dialog`) for viewing raw task payloads formatted in JSON.
  - Use `uilibs/components/base/alert-dialog` (`AlertDialog`) for destructive flush actions (`FlushPendingTasks`, `FlushCompletedTasks`).
  - Use `uilibs/components/extra/badge` (`Badge`) to distinguish pending vs dead queue tasks.

### D4: Timezone picker implementation
- **Decision**: In `packages/webapp/src/routes/(app)/-settings-view.tsx`, add an IANA timezone Select control seeded by `Intl.supportedValuesOf('timeZone')` (or standard curated fallback list), preselected to `user.metadata.timezone` or browser `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- **Rationale**: Directly resolves the long-standing `TODO(frontend)` in `modules/identity/user/service.go:346`.
