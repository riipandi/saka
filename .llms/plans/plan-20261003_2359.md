## Plan: storage revamp — buckets, /storage serving, tus upload

### Objective

Close the file-storage revamp the owner settled on 2026-10-03:

- A bucket layer over the file storage engine, modeled on the Supabase
  storage schema (`buckets`, `objects` — no vector, analytics, or multipart
  tables), so features and administrators address files as
  `BUCKET_NAME/folder/file` on both the local filesystem and S3.
- Serving moves from `/static/*` (the copy-for-URL uploads directory) to
  `GET /storage/{bucket}/{key}`, with `app.assets_url` (`PUBLIC_ASSETS_URL`)
  as the base a CDN deployment points at.
- The tus resumable-upload protocol, implemented in-house (protocol only,
  no tusd library), so the frontend integrates through tus client SDKs and
  large uploads survive network interruption.
- Administrators manage buckets through the RPC surface; the default
  bucket is a setting in the database (`appconfig`), not a config-file key.

Flow references: the Supabase storage schema compiled from the **full
tenant migration set** (`supabase/storage` `migrations/tenant/`
`0001`–`0073`, applied in order against a throwaway Postgres 16 on
2026-10-03; 72 of 73 applied — only `0047-iceberg-table-metadata` failed,
an Iceberg analytics feature this plan excludes — and the resulting
`storage` schema is dumped verbatim in
`.llms/references/supabase-storage-schema.sql`) and the tus protocol
specification (tus.io `protocols/resumable-upload`, read 2026-10-03).
Deltas from both are decisions below, each with its reason.

### Current state

Every claim verified in the tree on 2026-10-03.

- **Schema** — `database/migrations/00009_create_filestore_tables.sql`
  creates one table, `public.storage_files`: `id` UUIDv7, `key` TEXT with
  `UNIQUE (key)` global, `size`, `content_hash`, `status`
  (`pending|ready|failed`), `metadata` JSONB, `staging_size`,
  `staging_mtime`, timestamps with an update trigger. Its Down also drops
  the residue `storage_chunks` table. Migrations after it run to `00016`.
- **Engine** — `internal/storage/manager.go`: `Stage` writes the staging
  file through a temp file + rename and commits the intent row before the
  upload; `Sync` hashes (SHA-256, fingerprint-trusted reuse), PUTs the file
  whole, commits the ready manifest, and clears staging under a TOCTOU
  fingerprint guard; `Delete` removes the row first, the object second;
  `CollectGarbage` diffs the backend listing against
  `Manifests.StoredKeys` (the whole table's key set). Hooks
  `WithBeforeSync` / `WithAfterSync` are wired in the registry.
- **Key vocabulary** — `internal/storage/storage.go`: `Key(parts...)`
  composes safe path segments; `ValidateKey` refuses traversal, absolute,
  and hidden segments. Keys are feature-composed (`avatars/<id>.<ext>`,
  `oidc-logos/<client_id>.<ext>`) and globally unique because the table
  says so.
- **Backends** — the local driver writes finals under
  `storage.local_path/files/<key>` (its own namespace, not served); the S3
  driver writes under the configured `PathPrefix` in the single
  `storage.s3.bucket_name` (`internal/config/types.go:611-669`). One
  driver is constructed, selected by `storage.driver`.
- **Staging + watcher** — staging is `storage.local_path/staging`; the
  watcher (`internal/storage/watcher.go`) watches every directory under
  it, debounces per path, scans at start, and hands the relative path as
  the key to the upload enqueue. There is no bucket dimension anywhere in
  this path.
- **Serving** — `internal/transport/static` mounts `/static`
  (`static.go:32`, `router_http.go:199`, outside the guarded/rate-limited
  group, before the SPA) over `storage.local_path/uploads`
  (`config.UploadsDir`, `internal/config/defaults.go:29`). A feature that
  wants a URL writes a whole copy under `uploads/`; the engine's `files/`
  tree is never served.
- **Progress** — `GET /api/uploads/{key...}` is the transport's own route
  (`internal/transport/uploads_progress.go`), guarded `Authenticated` in
  `internal/guard/rules.go:519`, answering the manifest's status and size.
- **Consumers today** — avatar
  (`modules/identity/user/picture.go:112-171`): sniff → key
  `avatars/<id>.<ext>` → `Stage` → `Sync` → `SetAvatarURL` (the row stores
  the **key**, not a URL) → audit; read is a public REST picture route
  (`guard/rules.go` identity block, redirect to the bundled default when
  absent). OIDC client logo (`modules/federation/oidc/logo.go`): same
  shape, staged and synced in-request.
- **Jobs** — `storage_upload` (task type still named `ChunkUploadTask`)
  and the recurring `storage_gc` are registered in `internal/jobs`.
- **Settings** — `modules/appconfig/settings.go`: `SettingDef` catalog
  (key, default, sealed, public) declared in code, table holds overrides,
  cached reads; keys like `oidc.*`, `access.mode`.
- **RPC surface** — `api/connect/*.proto` holds thirteen services; no
  storage proto exists. Guard rules live in `internal/guard/rules.go`
  (`ProcedureRules`, `RestRules`).
- **Queue precedent for in-house protocol adoption** — `internal/queue` is
  a port of Backlite ported to the house rules and no longer tracked
  upstream (`internal/queue/README.md:6-9`). That is the pattern this plan
  follows for tus: adopt the specification, own the implementation.

### Decisions

Dated 2026-10-03, settled with the owner in the research thread. Binding.

1. **Buckets are logical namespaces over one configured backend.** A
   bucket row names a first path segment; the physical backend (local
   directory or the one configured S3 bucket) and its credentials stay in
   the config file. Rejected: per-bucket physical backends with
   database-held credentials — a deployment system, not a namespace, and
   it moves secrets into the database.
2. **Tables `storage_buckets` and `storage_objects`** (Supabase naming,
   snake-cased into the `public` schema; `storage_files` is renamed, not
   paralleled). Rejected: keeping `storage_files` beside a new table —
   two manifest representations is the drift the chunk-store removal
   already paid to avoid.
3. **Migration edited in place.** `00009_create_filestore_tables.sql` is
   rewritten to create both tables (the Down keeps the `storage_chunks`
   drop). No ALTER migration files. A dev database reset
   (`task db:reset -- --force --up`, then `task db:seed -- --force`) is
   authorized for this plan. Rejected: a 00017 ALTER migration — the owner
   explicitly waived backward compatibility.
4. **Path layout `BUCKET_NAME/folder/file` on both drivers.** Local
   finals: `storage.local_path/{bucket}/{key}` (the `files/` namespace
   dies). S3: `{PathPrefix}/{bucket}/{key}`; a CDN fronting the S3 bucket
   directly requires an empty `PathPrefix` so the object path mirrors the
   public path — documented for operators, not encoded.
5. **Serving: `GET /storage/{bucket}/{key}`** — the first segment is
   resolved against `storage_buckets` (a directory that exists on disk but
   names no bucket is a 404, never a listing), the rest is
   `ValidateKey`-checked, and the bytes stream from the active backend
   (local disk or `Manager.Open`'s S3 read). Immutable cache headers and
   the not-found boundary carry over from `static`. Rejected: redirecting
   S3 reads to presigned URLs — the public URL shape would depend on the
   driver. Rejected: serving all buckets through the bare directory —
   `staging/`, `logs/`, `backup/`, and `config/` live beside the buckets.
6. **`/static` and the copy-for-URL convention are removed**, not
   deprecated. `config.UploadsDir` and the `uploads/` tree die with it.
   Consumers name their key and build `app.assets_url + /{bucket}/{key}`.
7. **`app.assets_url` default becomes `/storage`** (was `/static`); the
   `PUBLIC_ASSETS_URL` variable a deployment sets may name a CDN origin
   whose path layout mirrors `/{bucket}/{key}`. `sample.go`'s
   `envKeys`/sample docs follow.
8. **tus, protocol only, implemented in-house.** Core methods:
   `POST` creation (`Upload-Length`, `Upload-Metadata`), `HEAD`
   (`Upload-Offset`), `PATCH` (append at offset, refuse a mismatched
   offset), `OPTIONS`. Extensions shipped: `creation-with-upload` (small
   files in one request — the shape the avatar/logo paths already use),
   `termination` (DELETE), `expiration` (abandoned uploads expire).
   Rejected: embedding `tusd/pkg/handler` — its filestore holds metadata
   in `.info` files (not the manifest), its s3store writes a layout the
   GC vocabulary cannot name, and it would run a second auth surface
   beside the guard. Rejected: `concatenation` and `checksum` extensions —
   no consumer asks for them yet.
9. **tus endpoint: `/api/uploads`** (creation, `/{id}` for HEAD/PATCH/
   DELETE), mounted by the transport, guarded `Authenticated` through the
   REST bearer middleware — creation demands an existing bucket, a valid
   key, and the bucket's `file_size_limit`. Any signed-in account may
   upload into any bucket for now; per-bucket write permissions are the
   follow-up surface, named in out-of-scope. Rejected: an RPC-issued
   upload ticket — one more round trip for a surface that has no
   per-bucket authorization model yet to gate on.
10. **Staging gains the bucket dimension**: tus writes stage under
    `staging/{bucket}/{key}`, so the watcher hands `bucket/key` and `Sync`
    resolves the bucket from the first segment — one staging tree, the
    same settle logic.
11. **Bucket deletion refuses a non-empty bucket** (the caller empties it
    first). Rejected: cascade delete ala Supabase — an administrator
    misfire should not have to be restored from a backup to be undone.
12. **Default bucket: the appconfig setting `storage.default_bucket`**,
    falling back to the seeded `default` bucket; the setting is validated
    against the buckets table at read time (a missing bucket is a
    refused stage, not a silent fallback). Rejected: a config-file key —
    the owner moved default selection into the database.
13. **Bucket management is Admin-gated RPC** (`saka.storage.v1
    .BucketService`: Create, Update, Delete, List, Get) in a new area
    `modules/storage` (feature `bucket`), with audit events
    `storage_bucket_created` / `_updated` / `_deleted` and the `default`
    bucket seeded. Rejected: permission slugs in the catalog on day one —
    the queue/scheduler precedent (Admin for the operational surface)
    fits until a non-admin needs the screen.
14. **Task type renamed** `ChunkUploadTask` → `StorageUploadTask` (the
    chunk name predates the whole-file shape; no compat is owed). Queue
    rows reset with the database.
15. **`avatar_url` stores `bucket/key`** — the row's value becomes
    unambiguous once keys are scoped per bucket. The public picture read
    resolves the bucket the same way `/storage` does.
16. **Compiled-schema deltas from Supabase** (final structure in
    `.llms/references/supabase-storage-schema.sql`, compiled 2026-10-03):
    - **Bucket primary key**: saka keeps a UUIDv7 `id` with `name` TEXT
      UNIQUE; Supabase uses a text `id` that *is* the bucket name.
      Rejected: text id — the house rule is UUIDv7 primary keys with a
      hash-plus-uuid for tokens, and a rename-able name column reads
      better than an id that secretly means the name.
    - **Uniqueness on objects**: saka takes a plain
      `UNIQUE (bucket_id, key)`. Supabase's final form is *partial*
      unique indexes (`... WHERE archived_at IS NULL`,
      `... WHERE NOT is_versioned`) because of object versioning
      (`0062`). Rejected: the partial-index shape — versioning is out of
      scope, and a partial index without a versioning feature is a
      constraint whose relaxation nobody can trigger.
    - **`path_tokens` generated column** (`string_to_array(name, '/')`,
      `0062` era) and the function-computed folder aggregation that
      replaced the old `prefixes` table — adopted *later*, with the
      folder-browsing surface it serves. No consumer exists yet.
    - **`last_accessed_at`** — Supabase tracks object reads; saka has no
      read-accounting consumer. Rejected for now.
    - **`owner` / `owner_id` columns** — Supabase carries a deprecated
      `owner` uuid beside `owner_id` text (JWT `sub`). Saka keeps the
      owner in `metadata` as it does today. Rejected: a dedicated column
      whose only reader would be the notification hook that already
      reads the metadata.
    - **Adopted as-is**: per-bucket `file_size_limit` BIGINT and
      `allowed_mime_types` TEXT[] (`0013`/`0014`, NULL = unlimited /
      any), and the bucket-name length rule (`0037`, 100 characters)
      enforced in Go at the service boundary instead of a database
      trigger. The `public` column is **not** created: a column nothing
      reads is dead schema, and the private-bucket follow-up adds it in
      the same change as the authenticated read path that consumes it.

### Shape and enforcement points

- **Tables** (migration `00009`, rewritten):
  - `storage_buckets`: `id` UUID PK `uuidv7()`, `name` TEXT
    `UNIQUE` (lowercase slug, ≤ 100 characters, validated in Go against
    one path-segment rule — the same characters `Key` accepts),
    `file_size_limit` BIGINT NULL (NULL = unlimited),
    `allowed_mime_types` TEXT[] NULL (NULL = any),
    `created_at` / `updated_at` TIMESTAMPTZ with the update trigger.
  - `storage_objects`: the `storage_files` columns with `bucket_id`
    UUID NOT NULL referencing `storage_buckets(id)` ON DELETE RESTRICT
    (deletion refuses a non-empty bucket, decision 11),
    `UNIQUE (bucket_id, key)` replacing the global one, and a
    `storage_objects` / `storage_objects_updated_at` naming for the
    trigger.
- **Seeder**: `DefaultBucketSeeder` in `database/seeders/`, `ON CONFLICT
  DO NOTHING`, appended to `All()` in dependency order (after identity).
- **Engine** (`internal/storage`): the `Manager` API takes a bucket
  argument (`Stage(ctx, bucket, key, r, metadata)` and friends);
  `Manifests` joins `storage_buckets`; `StoredKeys` scopes per bucket so
  `CollectGarbage` diffs only the bucket's prefix; `Open` resolves
  through the bucket. `Progress` answers for a bucket-scoped key.
- **Serving** (`internal/transport/static` → renamed `storage` mount):
  bucket-aware driver, mounted at `/storage` outside the guarded group,
  before the SPA; a missing bucket, an invalid key, and a missing object
  are all 404, never `index.html`.
- **tus handler** (`internal/storage/tus*.go`): protocol handler beside
  the engine (it reads and writes staging and manifests through the
  `Manager`), mounted by the transport at `/api/uploads`; the
  `Tus-Resumable` version pinned at `1.0.0`.
- **RPC** (`api/connect/storage.proto`, `modules/storage/bucket/`):
  `saka.storage.v1.BucketService` — `CreateBucket`, `UpdateBucket`,
  `DeleteBucket`, `ListBuckets`, `GetBucket`; constraints as
  `buf.validate.field`; area `Package` + `Mount` + one `registry.Areas()`
  entry.
- **Guard**: bucket procedures under `Admin` in `ProcedureRules`;
  `/api/uploads` creation and item routes under `Authenticated` in
  `RestRules`; `/storage/{bucket}/{key...}` is public like `/static` was
  (mounted outside the guarded group, so it never enters `RestRules`).
- **Settings**: `SettingStorageDefaultBucket = "storage.default_bucket"`
  in the appconfig catalog (public: false, sealed: false, description
  names the fallback).
- **Config**: `app.assets_url` default `/storage`; no new storage keys —
  the bucket layer is not configurable, it is data.
- **Audit**: three bucket events in `internal/audit/audit.go`.
- **Frontend** (`web`): `tus-js-client` dependency; the avatar upload
  switches to tus creation-with-upload; any `/static/…` URL composition
  becomes `assets_url + /storage/…`.
- **Yaak** (`api/specs/` mirror via the `yaak` CLI, `[Saka]` labels):
  five bucket requests, tus endpoint requests (creation / HEAD / PATCH /
  DELETE / OPTIONS), and updated picture/avatar requests wherever the
  response shape or parameters move — each rides the phase that changes
  the contract.

### Execution rules

- Each phase lands as **exactly one atomic commit** — its own heading
  names the message, its file list is limited to that phase's work, and
  no phase carries another's files. The commit follows the phase's
  validation passing; a phase that cannot validate stops and reports
  rather than commits. The hash lands in the phase's frontmatter
  `commits` entry, together with the `status` move and the body, in the
  same commit. The standing commit rule resumes when the plan completes.
- Dev-database reset is authorized (`task db:reset -- --force --up`,
  `task db:seed -- --force`). Migration `00009` is edited in place; no
  ALTER migration files are written. No legacy or compatibility shims are
  owed: no dual reads, no fallback paths for the pre-bucket layout.
- Yaak updates ride the same change as the contract they describe.
- Per-phase validation runs before each commit; a phase that cannot
  validate stops and reports rather than commits.
- The closing phase owns the docs sync (architecture, endpoint reference,
  AGENTS.md implemented-list, README tasks if a task changes).

| Debug probe | `/debug/file-upload` in a debug build; release build answers 404 | upload, pause + resume, termination, serve link all work in the page |
| Lint | repo lint task | clean, no `//nolint` |

### Explicitly out of scope

- **Private buckets** — every bucket is publicly served at
  `/storage/{bucket}/{key}`; the owner's serving spec has no private
  concept. A `public` flag and an authenticated object read are the named
  follow-up when a feature stores user-private files.
- **Per-bucket physical backends** — one driver, one S3 bucket, one
  credential set, from the config file.
- **S3 multipart sync** — the 5 GiB single-PUT ceiling stands as a
  deployment ceiling; `s3_multipart_uploads` tables are not created.
- **Fine-grained upload authorization** — any authenticated account may
  upload into any bucket (within bucket limits); per-bucket permission
  slugs are the follow-up.
- **Object versioning, search/prefix browsing UI, lifecycle rules** —
  Supabase features with no consumer here yet.
- **CDN edge behavior** — a CDN deployment owns its origin setup; the
  plan only guarantees the path layout it must mirror.
