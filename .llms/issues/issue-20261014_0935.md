## ISS-002 — enable RFC 8707 resource indicators on the provider

- Status: considering (trigger: the first internal MCP server lands) ·
  updated 2026-10-14 (re-verified)
- Plan: none yet — derived from the analysis in `.llms/openid.md`
  ("Internal MCP servers"); the first MCP work should plan it
- Area: OIDC protocol
- MCP servers must validate the token's audience against their own
  canonical URI; without the binding, one MCP server accepts tokens
  minted for another. The engine supports it
  (`provider.WithResourceIndicators` + `WithResourceIndicatorsRequired`,
  `pkg/provider/option.go:1588`) — the provider is built without it.
  Re-verified 2026-10-14: the option exists in the pinned
  `github.com/luikyv/go-oidc@v0.25.0` (`pkg/provider/option.go:1590`) and
  the provider build (`modules/federation/oidc/protocol.go:127–164+`)
  names no resource-indicator option.
  MCP clients send `resource` regardless, so enabling is backward-safe.
- Note: the metadata members the enablement implies need the same
  discovery treatment the back-channel members got (decorator).
