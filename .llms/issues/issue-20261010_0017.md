## ISS-004 — AssetsURL's public claim disagrees with the code

- Status: considering (trigger: the first deployment that serves the SPA
  assets from anywhere but the embedded binary) · updated 2026-10-10
- Plan: none — found in the Yaak reconciliation
- Area: configuration publisher
- `internal/config/publish.go:57` comments `AssetsURL` as "public — the
  SPA loads its assets from it", but `Published(full bool)` fills the
  field only in the full (administrator) scope (`publish.go:346`): the
  public body omits it. The embedded-SPA deployment never reads the
  field, so nothing breaks today — but the comment and the code cannot
  both be right, and a CDN-fronted deployment would build on the comment
  and get an empty value.
- Work: pick one — either the field joins the public scope (with the
  publisher test pinning it) or the comment is corrected to say the
  field is administrative. A one-line decision; no migration.
- Unblock: the first split-assets deployment decision.
