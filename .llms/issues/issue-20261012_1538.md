# Hardcoded seeder counts drift on every new seed item

- status: open
- plans: —
- trigger: any commit that adds a seeder entry (permission, setting, user, …)

`cmd/migrate_seed_test.go` asserts the seed command's summary line with
hardcoded counts (e.g. `"status: 152 created, 1 skipped"`, `"134 to create,
5 to skip"`) in four places. Every commit that adds a seed item must bump all
of them by hand — the backend debug-tags CI job went red (run #292) when
28 new seed items landed without the bump.

Consider deriving the expected totals from the seeder registry itself (the
command already knows what it will run), so the tests keep asserting the
status line's shape and the created/skipped invariants without a manual
counter to maintain. Reopen this whenever a seed-count assertion fails in CI
again.
