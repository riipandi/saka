# A dead auth worker hangs every in-flight Comlink call — the boot can go silent

Found while auditing the dev-mode StyleX bug (2026-10-09): the auth worker
crashed on every dev load (the React barrel reaching the worker realm —
fixed in the same audit), and the crash left `#root` empty with no console
error. The chain:

1. `authWorker()` wraps the Comlink proxy in `withCookies` and returns it.
   A caller (`ensureSessionLoaded` → `restore()`) awaits a Comlink call on
   that proxy.
2. The worker script dies mid-boot (a load failure, an extension, any
   script error). The `error` listener swaps `client` to a main-thread
   engine and re-restores — but that only serves **future** `authWorker()`
   callers. The caller already holding the dead proxy awaits a Comlink
   promise that no realm will ever settle.
3. `beforeLoad` never resolves → the router renders nothing → a blank page
   with zero console errors. The probe reproduced it deterministically
   (`route.abort` on the worker file → form never renders, no errors).

What the fix in this audit did NOT change: in-flight calls on the swapped-out
proxy still hang. A robust shape would route `withCookies`' calls through a
mutable current-engine reference AND bound each Comlink call (a timeout or a
liveness race) so a dead worker rejects instead of hanging — then the
fallback engine takes over mid-boot.

Trigger: any report of a blank first paint in dev, or a worker crash in a
real browser (extensions are the documented cause); or whenever the auth
worker boundary is touched next.
